BMS 系统原理与开发路线

你要理解的是一条完整的链路：把电池的物理状态变成数字 → 根据目标计算控制量 → 用功率电路改变电流 → 再测量、再修正。电脑上的开发软件和上位机分别负责生成程序、观察与安排实验。

先把最容易混在一起的四个概念放到正确位置：ADBMS1818 自带 ADC；STM32 通过 SPI 读它的数字结果。STM32 自己还有另一套 ADC。HEX 是烧入板子的固件；上位机是运行在电脑上的 EXE。

本页解释“目标系统应该怎样工作”，同时标明“目录里现在实现到哪里”。演示中的数值是教学模型或示例，不是实测结果，也不是可直接下发到电池板的控制参数。页面不会访问串口或启动硬件输出。

01 / 全局地图

系统分成哪些层

主控是整个系统的计算与调度中心，但测量和控制还需要传感器、信号调理、功率器件、驱动和通信。软件也不是只有一个 BSP。

层次这一层有什么它解决什么问题
① 被测对象与能量通路三节电池、电源、负载、电感、MOSFET、继电器电池储能；电源、负载和功率级承担实际能量流动。
② 传感与模拟前端分流电阻、电流放大器、PT1000 分压电路、ADBMS1818把电压、电流、温度变成可测的模拟电压，完成部分高精度转换。
③ 主控与硬件外设STM32 的 CPU、ADC、TIM、DMA、GPIO、SPI、I2C、USART读数据、精确定时、产生 PWM、搬运数据和对外通信。
④ 底层软件CMSIS、HAL、BSP把寄存器和器件操作包装成可调用函数。
⑤ 板端应用与算法采样调度、PI、充放电状态机、保护、命令解析、SOC 推理决定何时采、怎样控制、能否启动、遇到异常如何停止。
⑥ 电脑端工具Keil、CubeProgrammer、上位机、训练脚本、未来的 MCP 服务生成和下载固件，配置实验，保存与分析数据，辅助迭代开发。

CPU 执行算法，外设承担精确的硬件动作。例如 CPU 不需要不停翻转引脚来“手搓”100 kHz 方波；它配置好 TIM 后，定时器硬件持续输出 PWM。CPU 只需要按控制周期更新占空比。

代码中的调用关系通常是：应用 main/控制任务 → BSP 器件驱动 → HAL 外设接口 → 寄存器与硬件。CMSIS 提供内核、寄存器、编译器适配等基础定义。这是帮助理解的层次，实际代码也允许应用直接调用 HAL。

02 / 谁在采样

ADBMS1818 是什么，和 STM32 ADC 是什么关系

ADBMS1818 是 ADI 的多节电池监测芯片，也是一种电池监测模拟前端。它能监测最多 18 节串联电池，内部含 3 个 ADC 转换单元、测量多路选择、结果寄存器、通信接口和被动均衡控制。18 路电芯输入不等于 18 个独立 ADC。它不是负责运行整个 BMS 应用的通用主控。[ADI]

ADC 的意思是“模数转换器”：把某时刻的模拟电压转成一个数字码。ADC 不会天然知道这个电压代表“安培”还是“摄氏度”；物理意义来自前面的传感电路和后面的换算公式。

通路 A：通过 ADBMS1818 做电池监测

电芯端电压 / 传感电压连续的模拟信号
→
ADBMS1818 内部 ADC完成模数转换
→
芯片结果寄存器保存数字码
→
SPI5 → STM32读字节、校验、换算

通路 B：通过 STM32 自己的 ADC 做快速电流反馈

实验目标，当前源码尚未接通这条闭环。

电流检测输出电压从模拟电路引出
→
PA1 → ADC1TIM1 触发转换
→
ADC 完成中断 → PI算电流与占空比
→
TIM1 → 功率级改变实际电流
STM32 不需要用自己的 ADC 再采一次 ADBMS 的结果。ADBMS 已经把模拟量数字化，主控通过 SPI 读数字。第二条通路测的是电流放大器输出的模拟电压，不是把 SPI 数据送入 ADC。

代码能确认两条通路都用于电流测量，但不能仅由代码确定它们是否接在完全相同的模拟节点、是否具有相同偏置与灵敏度；这要对照原理图和实测分别确认。

ADBMS1818 内部具体做了什么

  • 电芯测量输入：测相邻电芯抽头之间的电压，区分每一节电池。18 通道能力不代表这个项目装了 18 节电池；当前代码使用通道 1、7、13 对应三节电池。
  • AUX 辅助测量：芯片的一些 GPIO 可作为模拟测量输入。当前代码把 GPIO1 用于电流检测电压，GPIO2/3/4 用于温度分压电压。这些是 ADBMS 的 GPIO，不是 STM32 的 PA1 等引脚。
  • 通信：器件支持 SPI 与 isoSPI 等连接方式；本项目源码使用 STM32 的 SPI5。isoSPI 服务隔离/级联等系统连接需求，不等于当前项目一定用了该连接方式。
  • PEC 校验：读回报文附有包错误校验码，用来发现通信数据是否损坏；它不能代替传感器标定。
  • 被动均衡：控制某节电池通过放电电阻释放少量能量，让较高电压电芯向其他电芯靠近。它与用大功率 DC-DC 控制整组电池电流是两件事。

软件怎样完成一次 AFE 采样

  1. 唤醒器件并配置所需基准、通道与转换模式。
  2. 通过 SPI 发“开始电芯转换”或“开始辅助通道转换”的命令。
  3. 等待转换完成，最好按芯片规定轮询完成状态或使用与模式匹配的等待时间。
  4. 读结果寄存器，校验 PEC，按字节序组合数字码。
  5. 按标定系数换算成伏、安培、摄氏度，并传递有效性标志。

当前代码已有这条采样流程，但只在启动时调用一次。后续仍要核对转换等待时间、错误状态传播和传感器标定。寄存器读取的先后与转换完成条件应以数据表为准，不能只依赖源码注释。

03 / 数字怎样变成物理量

电压直接测，电流和温度通过电路转换后测

想知道的量前端怎么产生可测电压软件怎么还原
电芯电压 V电芯抽头接到电池监测输入ADBMS 电压码 × 对应量程系数
电流 I电流经过分流电阻产生压降，再放大并加零点偏置去掉零点电压，再除以“增益 × 分流电阻”
温度 TPT1000 电阻随温度变化；分压电路把阻值变化变成电压变化先由分压反算电阻，再由传感器模型反算温度

电压码：注意两种 ADC 的换算不同

本项目 ADBMS 读数：V = raw × 0.0001 V
示例：raw = 37,000 → V = 3.7000 V

本项目 MCU 12 位 ADC 示例：V ≈ code / 4095 × VREF

ADBMS 数据寄存器中每个结果按 16 位值读取，但数据表规定的 100 μV/码不等于“用 VREF2 除以 65535”。STM32 的 ADC 位数、参考电压和过采样又是另一套配置。这里用 4095 做工程换算示例；精确标定还应考虑量化定义、参考误差、偏置和增益误差。[ADI]

电流：零点偏置让正负方向都能测

Vsense = Vzero + G · Rshunt · I
I = (Vsense − Vzero) / (G · Rshunt)

按课程约定，流向电池为正，即充电为正、放电为负。资料里的零点约为 0.9 V。若假设增益 G = 50、分流电阻 R = 0.015 Ω，则灵敏度是 0.75 V/A。测到 0.525 V 时，I = (0.525 − 0.9) / 0.75 = −0.5 A。这里“50 倍”只是按资料给出的假设计算。

这份资料有一个要先核实的型号问题：它把 INA199A2 写成 50 倍，但 TI 官方规定 INA199x1 为 50、x2 为 100、x3 为 200。若实际装的是 A2，且没有其他改变比例的电路，就不能直接套 0.75 V/A。最终系数应由实物型号、原理图和已知电流的实测标定确认。[TI]

试着把 MCU ADC 码换成电流

固定使用 VREF = 1.8 V、Rshunt = 15 mΩ 的教学假设。改变增益，观察同一个 ADC 码会对应怎样不同的电流。

标定至少要确定零点、灵敏度和方向。零电流时采样得到零点；用可靠仪表测几组已知电流，拟合码值与电流的关系；分别验证充电和放电的符号。零点不应只凭理论永远写死为 2048。

温度：当前模板按 PT1000 换算

上拉电阻 Rup 接 Vexc，PT1000 接地：
RPT = Rup · V / (Vexc − V)
T ≈ (RPT / R0 − 1) / α
模板参数：Rup = 9.1 kΩ，Vexc = 3.0 V，R0 = 1000 Ω，α = 0.00385 /°C

例如 V ≈ 0.3226 V，对应 R ≈ 1096.25 Ω，在线性近似下约为 25 °C。VREF2 在这里是分压的激励电压。这个线性式适合解释原理，准确范围需要按传感器规格和标定确定。开路、短路、PEC 失败应返回“无效/故障”，不能照常算出一个温度。

模板源码使用 PT1000；上位机手册有 NTC 字样。两种传感器的阻温模型不同，属于资料需核对的地方。不能因上位机有温度栏，就认为任一传感器都能使用同一公式。

04 / 主控不是只有 CPU

STM32 内部各个硬件模块做什么

模块直观理解在当前项目中的位置
CPU / Cortex-M55执行 C 代码编译后的机器指令算电流、执行 PI、处理模式和协议；后续可运行模型推理。
ADC1 / ADC2把引脚上的模拟电压转为数字ADC1 已配 PA1 电流通道；ADC2 源码配置了电压通道。当前都尚未启动采样。
TIM1有专门比较和输出逻辑的硬件计数器产生互补 PWM；更新事件可触发 ADC。调占空比主要改比较寄存器 CCR。
GPIO数字引脚输入/输出读按键，开关继电器，控制 LED、SPI 片选。
SPI5主控提供时钟的同步数字通信总线对 ADBMS 发命令、读测量寄存器。
I2C4使用 SCL/SDA 的地址式数字总线给 OLED 发送显示命令和像素数据。
USART1按约定波特率收发字节经 USB 转串口接口连接电脑；当前 115200、8N1。
DMA按配置自动搬运数据目前用于 OLED 和串口发送，减少 CPU 逐字节搬运；不替你解释物理意义。
NVIC / 中断在硬件事件发生时让 CPU 转去处理ADC 转换完成后可以及时运行 PI。优先级和最坏执行时间决定能否按时完成。
SRAM、Cache、XSPI运行数据、加速访问、连接外部存储程序发布到外部 NOR；HyperRAM 提供扩展内存。DMA 与 Cache 一致性需正确处理。
NPU专门加速兼容的神经网络运算是后续 SOC 模型部署的可用资源；有 NPU 不等于工程已经有 AI 模型。[ST]

快任务和慢任务要分开安排

TIM1 更新事件硬件触发
→
ADC 转换完成获得这次的新采样
→
中断内换算与 PI计算新的 D
→
写 CCR 预装载按定时器配置生效

课程目标是 PWM 和控制更新都为 100 kHz，即一轮约 10 μs；实际是否达到，必须测执行时间和触发频率。按键约 10 ms 扫描一次，OLED 和遥测约 1 s 更新一次，放在慢任务里。串口打印、屏幕刷新、延时等待不能塞进这个快速 PI 回调。

当前代码为中心对齐计数、ARR = 2000、RCR = 1、TRGO = UPDATE。RCR 配置用于控制更新事件的重复节奏；真正的采样相位还取决于定时器启动、触发路径和转换延迟，要用波形核对，不能仅凭一个配置名就认定“采到了理想平均值”。

05 / 数字指令怎样改变能量流

TIM 输出 PWM，功率级把它变成电流控制

PWM 是“周期固定、导通时间可变”的开关信号。TIM 引脚输出的是逻辑控制信号。门极驱动器把它转换成适合驱动 MOSFET 的电压和电流；MOSFET 开关、电感储能及电容滤波共同完成能量变换。

TIM1 / PWM决定开关时刻
→
门极驱动器驱动上下管栅极
→
MOSFET + L + C传递和调节能量
→
电池 / 母线电流与功率发生变化

同一组开关，两个能量方向

模式能量方向理想稳态关系与含义
充电 Buck较高电压母线 → 电池Vbat ≈ D · Vbus，上管导通比例决定开关节点的平均电压。
放电 Boost电池 → 较高电压母线Vbus ≈ Vbat / D；此处仍用上管占空比 D。

本页始终定义 D = 上管有效导通占空比。教材常见 Boost 公式 Vout = Vin / (1 − Dlow)，其中 Dlow 指下管占空比。在理想互补条件下 Dlow ≈ 1 − D，所以两式一致。混淆这个 D，会把调节方向判断反。以上关系是理想、连续电流、忽略损耗的近似。[TI]

为什么改变 D 会改变电流

开关节点平均电压：V̄SW ≈ D · Vbus
简化平均模型：L · di/dt = D · Vbus − Vbat − R · i

电池有自己的端电压，不能像一个纯电阻一样随意把它的电压“设成任何值”。控制器改变 D，会改变电感两端的平均压差，进而改变电流增长或减小的速度。电流建立后，端口功率约为 P = V × I。电池电压、损耗和负载都在影响实际结果，因此固定占空比不能保证固定电流。

例如母线 16 V、电池 12 V，忽略损耗时平衡点约为 D = 0.75。在 i 接近 0 时，把 D 略微增大，电流开始向充电方向增长；略微减小，电流朝放电方向变化。电流不会瞬间翻转，实际变化还受 L、R、初始电流和外部电路约束。

改变占空比，观察两路互补信号

波形按占空比解释互补关系，省略死区；不表示当前板子已经输出这些信号。工程目标 100 kHz 对应周期 10 μs。中心对齐时 TIM 时钟、PSC 和 ARR 共同决定频率；资料按 TIM 时钟 400 MHz、PSC=0、ARR=2000 得到约 100 kHz，真实时钟仍需核验。

上下管不能同时导通。互补 PWM 通常配合死区避免直通；资料称 EG3112 驱动具有死区，当前 TIM 配置 DeadTime=0。因此需确认实际驱动输出和关断时序，不能把“逻辑互补”直接等同于功率级已经验证。[ST]

06 / 控制理论落到代码

PI 就是自动控制课程里的 PI 控制器

是的，它与 P、PD、PID 属于同一套反馈控制思想。这里控制的对象是电池电流，控制器输出是 PWM 占空比。把“电流误差”转换成“占空比修正”的规则，就叫控制算法。

给定 iref例如 +0.50 A
→
误差 e = iref − i测量 i = +0.40 A
所以 e = +0.10 A
→
PI + 限幅得到新的占空比 D
→
功率级响应再测 i，下一轮继续

P、I、D 分别在做什么

项公式作用与代价
P：比例Kp · e(t)当前误差越大，立即修正越多。增益过大可能放大噪声，并在延迟存在时引起振荡。
I：积分Ki · ∫e(t)dt把持续偏差累积起来，逐步找到维持目标所需的输出。即使最后误差为零，积分仍能保留工作点。
D：微分Kd · de(t)/dt根据误差变化趋势作出反应，某些对象可改善阻尼；也容易放大测量噪声，需要滤波和谨慎设计。
P：u = Kp · e
PI：u = Kp · e + Ki · ∫e dt
PD：u = Kp · e + Kd · de/dt
PID：u = Kp · e + Ki · ∫e dt + Kd · de/dt

对常见有损耗、扰动或偏置不准确的对象，P 单独控制通常需要保留一点误差，才能产生足够的修正；I 可以继续积累这点误差直到偏差减小。不能把“P 一定有稳态误差”当成对所有对象都成立的定律。

电流环通常先使用 PI。增加 D 不意味着自动更好：开关纹波、ADC 噪声、采样延迟都可能被微分放大。本项目先把 PI、采样时序与功率级调通，再讨论是否需要更复杂控制。若使用 Ti、Td 的另一种 PID 参数形式，通常有 Ki = Kp/Ti、Kd = Kp·Td，不能把不同软件中的参数名直接混用。

单片机里没有连续积分，只有每一拍的加法

采样周期 Ts = 1 / fcontrol
e[k] = iref[k] − imeas[k]
P[k] = Kp · e[k]
J[k] = J[k−1] + Ki · Ts · e[k]
u[k] = P[k] + J[k]
D[k] = clamp(u[k], Dmin, Dmax)

J 是保存下来的积分状态。下一次进入回调时要接着上一次的 J 累加，不能每次都把它清零。Kp 的量纲可理解为“占空比/A”，Ki 是“占空比/(A·s)”。Ts 变化会直接改变每拍积分量，所以把控制从 100 kHz 改成 10 kHz 后，不能仍假装 Ts 没变。

另一个常见写法是加上工作点前馈：D = clamp(Dff + P + J)，其中 Dff 可以取近似 Vbat/Vbus。这时积分状态表示对工作点的修正。也可以不显式写 Dff，而把所需工作点放在积分初值里；两种写法都要确保启动和换向时的初值合理。

算一拍给你看

仅为算术示例，取 Kp=0.07、Ki=90、Ts=10 μs、上一拍 J=0.75000、目标电流0.50 A、实测0.40 A：

运算本拍结果
误差e = 0.50 − 0.40 = 0.10 A
比例项P = 0.07 × 0.10 = 0.00700
积分增量ΔJ = 90 × 0.00001 × 0.10 = 0.00009
积分状态J = 0.75000 + 0.00009 = 0.75009
输出u = 0.00700 + 0.75009 = 0.75709
写比较值若 ARR=2000，则 CCR ≈ round(0.75709 × 2000) = 1514

下一拍再次测电流，重新计算。这个例子不证明该参数在真实硬件上稳定。充电为正、放电为负时，可以统一使用 e = iref − imeas；只要实际功率级确实满足“D 增大时，电流往更正方向变化”，负反馈方向就一致。

为什么必须处理积分饱和

假设控制器算出 D=1.30，硬件却只允许 D≤0.90。真正输出最多0.90，但误差若一直存在，普通积分会继续增大。等目标降低后，积累的状态还没退回来，输出可能仍长时间顶在上限，产生过冲或恢复迟缓。

仅限制最终 D 不够。常用做法是：条件积分——已经饱和且误差还把输出往更饱和方向推时，暂停累积；或者反算——用“实际受限输出与未限幅输出之差”修正积分状态。积分边界与占空比边界也不必是同一个数值范围。[MathWorks]

展开：带条件积分的教学伪代码 
// 教学结构：具体数值、故障处理和时序需按实际系统设计
float pi_step(float ref, float measured) {
    float e = ref - measured;
    float p = Kp * e;
    float next_j = clamp(j + Ki * Ts * e, J_MIN, J_MAX);
    float trial = duty_ff + p + next_j;

    bool push_high = (trial > D_MAX) && (e > 0);
    bool push_low  = (trial < D_MIN) && (e < 0);
    if (push_high || push_low) {
        next_j = j;              // 饱和时不继续朝错误方向积分
    }
    j = next_j;
    return clamp(duty_ff + p + j, D_MIN, D_MAX);
}

该结构假设“增大输出使被控电流更正”。测量无效、模式停止或保护触发时，应由状态机退出控制并关断，不能把异常数据继续送入 PI。换向、重启和参数切换还需要积分状态管理与电流给定斜坡。

展开：位置式与增量式，以及当前 pi.h 的状态

上面的 P+积分状态写法是位置式。忽略限幅、参数固定时，可以改写成增量式：

Δu[k] = Kp · (e[k] − e[k−1]) + Ki · Ts · e[k]
u[k] = u[k−1] + Δu[k]

当前 pi.h 虽然注释写“增量式”，实现实际上是位置式结构，并带输出限幅和反算。反算发生在积分限幅之后，所以最终积分值不保证仍在先前范围内；这需要按设计意图验证。pi.c 又是另一版不匹配的接口，尚未加入当前构建。它们目前都没有组成已运行、已验证的闭环。

一条命令怎样影响电池电流

  1. 在电脑界面输入目标电流并点击操作按钮。
  2. 上位机将操作编码成协议命令，通过串口发出。
  3. 板端解析并校验参数，状态机判断是否允许启动，再设置目标。
  4. 板端PI持续调PWM；每拍调节不需要电脑重新发命令。
  5. 板端低速上传测量值、模式、故障等，上位机显示和记录。

因此 CSV 是实验的记录结果，不是控制算法本身。上位机曲线看起来平滑，也不能单独证明100 kHz电流环没有振荡；要观察快动态，还需要示波器或固件内的高速缓冲采样。

现成上位机使用专用 bms ... 命令，讲义示例采用 set ...，模板目前只做原样回显。三者还没有在当前源码中统一。连接相同串口、使用相同波特率，只保证能传字节，不保证协议能互相理解。

10 / 两种测试不是两种控制器

HPPC 和 DST 是电池测试工况

PI 解决“怎样跟踪给定电流”，HPPC/DST 解决“按什么时序给电池施加什么工况、要测什么特性”。它们处在不同层次：测试流程不断提供给定，底层控制器负责实现给定。

HPPC：混合脉冲功率特性测试

HPPC 是 Hybrid Pulse Power Characterization。在不同 SOC、温度等条件下施加规定的放电与回充脉冲，观察电压下降、恢复和上升，估计脉冲电阻与充放电功率能力。它也常为等效电路模型的参数辨识提供数据。

例如INL一版PHEV测试手册给出“10 s放电脉冲 → 40 s休息 → 10 s回充脉冲”，并在不同电量状态下重复。不同版本可能采用不同幅值和时序，不能把这个例子当成所有HPPC的唯一标准。[INL]

指定时间点的脉冲电阻近似：Rpulse ≈ |ΔV / ΔI|
示例：电流阶跃2 A，规定时刻电压变化0.12 V → R ≈ 0.06 Ω

必须说明“在阶跃后多久测ΔV”。瞬时压降和10秒后的压降包含的极化影响不同，不能都简单叫作纯欧姆内阻。项目手册中的1.25C、1.18C、1C等倍率也要按实际设置理解。C倍率与电池容量关联，例如额定容量1 Ah的电池，1C对应1 A；不能把1C固定理解成1 A。

DST：动态应力测试

DST 是 Dynamic Stress Test，通过连续变化的工况模拟动态使用：有负载变化、静置，也可有回充阶段。它让电池经历比单一恒流更丰富的输入，用于观察动态响应、评估性能，并检验SOC模型对变化工况的适应能力。

USABC原始DST包含360秒、20步骤、7个功率等级的变功率序列。本项目手册也写每轮360秒、20步，并以基础电流和倍率安排工况。按电流表执行与严格跟踪功率表不是同一件事：若目标是恒功率，通常要依据电压更新电流目标 Iref=Ptarget/V。未逐项核对映射前，应称“本项目采用的DST序列”。[USABC]

实验主要问题有用的记录
恒流与电流阶跃控制能否跟踪目标超调、稳定时间、稳态误差、占空比
HPPC电池在指定SOC下的脉冲响应如何电流/电压瞬态、恢复过程、脉冲电阻和功率能力
DST动态工况中性能与模型是否可靠时间序列、能量、电压响应、SOC估算误差

上位机能安排这些流程，但下位机仍要可靠地实现充放电、换向、保护和协议。本目录模板还没有这套完整业务；手册描述的是配套现成HEX的使用方式。

SOC 为什么还需要算法

电压、电流和温度是测量量；SOC是内部状态的估计。电池的端电压受电流、温度、滞回、老化等影响，同一个电压不一定对应唯一SOC。单凭一次电压读数通常不足以可靠确定剩余电量。

忽略效率损失的安时积分近似（充电电流为正）：
SOC[k] = SOC[k−1] + I[k] · Δt / (3600 · CN)
其中 CN 单位为Ah，Δt为秒，SOC以0～1表示。

例如1 Ah电池以0.5 A充电60秒，理想SOC增加0.5×60/3600≈0.00833，即0.833个百分点。初值、有效容量、电流零点、效率和采样时间误差都会影响积分结果；它可以作为经标定的实验基准，但不是天然无误差的“真值”。

课程希望利用实测V/I/T及可能的时间窗口训练CNN等轻量模型，学习它们与SOC的关系，再比较模型和基准。数据划分应防止相邻样本泄漏，例如按完整循环或工况分组划分；不能只靠训练误差低就声称泛化良好。恒流数据先建立基线，HPPC/DST可用于更丰富工况的测试或拓展。

第二阶段再接真实的flash_execute、test_start、test_stop和仪器接口。工具应使用已验证的板型、固件ID和测试配置，不应默认接受任意地址烧录、任意寄存器写入或不受约束的shell命令。上位机和MCP同时访问同一个COM口还需要统一所有权，通常不能各自直接独占打开。

怎样才算真的“闭环自我开发”

  1. 固定一个明确目标，例如“错误帧必须被拒绝”或“指定工况下稳态误差低于门限”。
  2. Codex修改一处代码，构建工具返回真实编译结果与固件哈希。
  3. 先运行离线验证；需要台架时按已定义测试执行，采集带时间戳的数据。
  4. 分析工具按预先确定的指标判定，而不是由模型看一眼就说“正常”。
  5. 未通过则保留证据，限制迭代次数，再修正；通过则保存版本与报告。

每次结果都要能追溯到源码 → target → 固件 → 板子 → 测量配置 → 本次数据。只有“编译成功”不能证明硬件正确；只有低速串口数据也不能证明快环稳定。若没有受控电源、负载、示波器或高速记录能力，自动化的证据范围就会受限。

接真实功率动作时，边界由本地系统强制执行

服务端和固件需要默认停止、参数边界、最大运行时间、失联超时、看门狗、异常关断和独立停止入口。台架还应有物理限流、可控能量路径与本地ARM条件。保护不能只靠模型记住提示词；Codex会改业务代码，所以关键物理限流和关断还应有独立保障。

MCP请求超时，不等于板子的PWM已经停止。必须由固件/本地控制服务规定超时后的动作，并在实际台架验证。开发闭环可以逐步自动化，但不应以无限制反复试错来替代功率系统的边界设计。

本轮只说明方案，并未创建MCP、修改Codex配置、连接串口、烧录或运行电池测试。最适合下一步做的是“桌面开发验证MCP”：构建、地址检查、假串口回放和测试报告，先证明它确实能发现并定位问题。

13 / 具体起点

建议按这个顺序学习和实现

1

先认清信号和文件

能画出两条采样链路，知道STM32 ADC与ADBMS ADC不同；能说清.c、BSP、Keil、HEX、上位机、加载器分别是什么。读main.c的启动流程，再读ADBMS和串口驱动。

2

建立能重复验证的测量基线

确认实际器件、传感器、参考电压、零点和增益。把采样做成周期任务，校验和错误状态完整；让屏幕/串口的数据与仪表一致。同步源码、IOC和构建结果。

3

分开验证PWM、功率级和ADC时序

先观察驱动波形，再按实验要求做受限开环记录；核对D定义、电流方向、触发相位和实际执行时间。不能靠上位机曲线代替这些证据。

4

接入一个统一的PI与状态机

统一pi接口，确定Ts、限幅、积分处理和给定斜坡；接通ADC→PI→CCR。再接停止、充放电换向、继电器互锁和保护。先本地稳定，再做远程设定。

5

做协议、记录与实验流程

决定兼容现成BMS上位机，还是先使用文本/VOFA+等简单协议。完整记录数据与状态，再逐步接恒流循环、HPPC和DST。

6

把离线开发验证交给MCP，再推进SOC

MCP先自动构建、检查、回放和出报告；硬件测试能力验证后再加入受限台架循环。与此同时积累真实数据，完成SOC标签、训练、量化和板端验证。

目前最值得先做的组合是：测量常量核对 + 工程配置同步 + PI接口统一 + 周期采样。它们完成后，后面的功率闭环、测试数据和模型结果才有可解释的基础。

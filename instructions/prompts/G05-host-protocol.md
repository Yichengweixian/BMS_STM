# G05：串口协议、记录器与上位机联调

## 可直接使用的提示词

请按本文件推进本阶段，并执行 [提示词入口的共同要求](README.md)。先核对当前状态、已有工作卡、证据与实际代码，再决定本次需要补做的部分。用户指定子任务时以其范围为准；未指定则依次完成当前条件支持的子任务。不要只给计划，完成已授权且可执行的实现与验证。

## 阅读与完成目标

阅读 [G05 验收条款](../specs/acceptance.md)、[数据规范](../specs/data.md)、hardware-profile 及现有串口/上位机资料。最小记录器可从 G01 提前准备，完整远程运行验收依赖 G04。

目标：使用户请求、主控实际应用值、运行状态和保存日志可对应，形成可靠的人机交互。

## 分解执行

### G05.1 定义协议契约
核对现成主机协议与固件实际行为，明确兼容方案。定义版本、帧边界、字段/单位/方向、序号、请求 ID、响应及错误码。定义 set 0、STOP、失联、重连、拒绝和钳位语义；实际值与请求值分开。

### G05.2 实现并测试解析
UART 回调只做有界接收/排队；解析支持分片、粘包及多帧，不把 IDLE 当完整帧保证。测试缺参数、未知命令、NaN/Inf、超范围、超长帧、重复/过期请求和坏校验。无效输入不能更改输出目标。

### G05.3 完善主机记录链
实现或适配最小串口记录器，保存原始收发与可追溯 CSV，显示设备身份、时间、单位、质量状态、请求/应用值。串口只保留一个控制所有者；重试遵守明确的幂等语义。先验证回放解析和异常处理。

### G05.4 接通业务状态机
远程启停、给定、按键及显示共同使用已验证状态机；STOP 取消不适用队列动作，重连不重放陈旧运行命令。失联策略在 MCU 本地执行。缺控制前置时只进行禁能通信验证。

### G05.5 长时记录与并发回归
按冻结窗口验证上传频率、丢帧、重复、复位识别、应答及断连/恢复。检查 OLED/主机显示与实际状态一致，通信压力下重验 G04 时序及 STOP 实际输出关闭。

## 必须交付与判定边界

协议文档、解析测试、记录工具源码、原始收发日志、断连/重连结果与并发回归。回显成功只证明基本通路；收到 ACK 不等于实际输出已关闭。

## 条件不足时继续做什么

主机 exe 无源码时先用协议资料和授权下的实际收发确认行为，开发可验证的最小记录器；不臆测封装软件内部实现。缺串口设备时继续回放、解析与工具测试。

完成后按 [统一交付格式](README.md)汇报，更新实际工作卡及必要的 STATUS/RUNLOG；没有完成的正式验证保持未判定。

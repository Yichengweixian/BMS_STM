用途：统一后续任务的顺序、分支、交付与进入下一步的条件。  
本次仅更新计划；没有修改固件、烧录或执行功率动作。阶段进度唯一入口仍是 [STATUS.md](STATUS.md)。

## 1. 两份计划的区别与关系

| 文件 | 回答的问题 | 使用方式 |
|---|---|---|
| 本文件《G03-无探头条件下的推进计划》 | 从现在到开环、PI、上位机、SOC和模型部署，先做什么，结果不同怎么办 | 后续任务的总路线与优先级入口 |
| [《G03-单次100ms继电器放电测试方案》](G03-单次100ms继电器放电测试方案.md) | 第一项实物探索具体如何实现、采集、停止和判读 | 执行下文任务1—2时使用的详细方案 |

旧总计划基于 r3，安排“先继续解决 ADC 一致性，再核实三路直流源台架，最后做 PWM 单点”。它没有纳入 r4 的结果，也没有把继电器单独作为第一项实验。本次将其更新为当前路线：

**单次继电器测试准备 → 一次真实通路观察 → 按结果分支 → 受限 PWM 单点与局部开环 → PI；上位机、数据工具和模型接口按依赖并行准备。**

不再要求先彻底解决 MCU 的1008／2048差异或先改接直流源，才能准备继电器实验。单次方案也不独立规定后续PWM/PI路线；这部分统一由本文件管理。旧文件原文保留在 [本次更新前快照目录](references/history/20261031-G03-roadmap-update/)。

## 2. 当前起点：沿用已经取得的结果

截至 [r4记录](../evidence/runs/20261031-G03-real-adc-r4/work-card.md)：

- 已移用HEX标称换算，修复基线与监控的采样节拍不一致；真实ADC禁能扫描、ADC看门狗、失联、STOP及既有回归已执行。
- r3的节拍跳变不再是待从头解决的问题；外部电流输入随工作方式变化的具体原因仍未闭合，物理电流标定未建立。
- AFE可提供真实电流原码和电芯数据，但现有约500ms应用采集不能保证覆盖100ms事件；真实AFE/电芯输入尚未接到拟议的继电器功率测试入口。
- 当前固件为禁能版，没有可直接执行新方案的继电器脉冲命令。合成状态机通过不等于真实功率控制已接通。
- 最近确认接线为三节真实电池、33Ω负载、充电口开路；这不是要求用户重新接线。具体硬件事实与未知项保持在 [hardware-profile](specs/hardware-profile.json)。

后续只因代码变化、失败或新疑点重测相关项目，不重复整套已经完成的禁能测试。HEX公式无需再次提取；只有对某个明确未解配置有帮助时才继续静态分析，也不把运行老师HEX设为必做步骤。

## 3. 近期任务：先取得一组真实响应

### 任务1：准备单次继电器测试入口

对应G03准备/控制及G05记录。由我完成实现、构建和验证；用户不需要接探头。

工作内容：

1. 独立的一次性入口：只控制PG5放电继电器，PB5充电继电器及PWM持续禁能；与已有测试分支互斥。
2. MCU本地最多100ms的GPIO高电平命令截止、STOP优先、异常锁存；重复请求不重做或延期，重启默认停止。
3. 专用AFE/电芯采集与缓存，保留动作前、命令窗口内、撤销后的有效样本及时间戳；串口输出不阻塞本地截止。
4. 原码、标称换算、错误/饱和/过期状态分开；physical_valid保持0。异常MCU电流模型不冒充准确的绝对限流。
5. 只验证新增或受影响的逻辑：期限、重复请求、STOP、数据失效、互斥、采样窗口覆盖及默认禁能。

交付：可审查的固件、构建身份、相关验证、主机命令、记录格式，以及本次工况表。工况表需固定基线比较规则、样本年龄、电芯退出条件、撤销后的观察期限和实际可用的电池侧断开方法；100ms只是命令期限，不证明触点或电气关断期限。

进入任务2的条件：以上准备完成，窗口内确能获得有效样本，本次动作所需的接线/运行边界/停止方法已明确，且会话已授权实际动作。已有授权不重复询问；本轮编写计划本身不启动输出。

### 任务2：执行一次100ms继电器通路探索

详细动作以 [单次方案](G03-单次100ms继电器放电测试方案.md) 为准。本任务只尝试取得真实“接通—响应—撤销后恢复”数据，不启动PWM、不自动重复。

交付：独立run、原始采样/收发日志、命令与采样时间、AFE原码和电芯曲线、停止原因、结论。没有取得有效窗口内样本时，必须写“观测不足”，不能写“没有电流”。

### 任务3：根据第一次结果选择后续工作

| 首次结果 | 下一项工作 | 该分支必须留下的结果 |
|---|---|---|
| 有清晰响应，撤销后恢复 | 在相同工况下规划少量独立重复；每次重新明确请求，不自动循环 | 响应方向、基线噪声、重复性、恢复过程及适用工况 |
| 有效窗口内没有明显变化 | 检查继电器命令与映射、AFE观测位置、课件通路假设和现有连接证据 | 能排除的原因、仍不能区分的具体连接；不自动加PWM或延长 |
| 窗口内采样不足、PEC/超时或过期 | 先修采集覆盖和数据有效性，在禁能条件验证相关修复 | 明确采样延迟和缺测原因，再重新制定实物运行 |
| 响应异常、饱和或电芯读数异常 | 停止并锁存，取消后续动作，检查本次原始数据与传感范围 | 失败记录与修改依据；不通过放宽阈值掩盖失败 |
| 撤销后不恢复 | 按预定方式终止供能；先处理实际停止路径 | 撤销命令与真实响应分开记录，不以GPIO LOW判定已物理断开 |

成功只支持已测的继电器通路和低速观测结果，不自动放行PWM或PI。失败也不回到“把所有软件再做一遍”：每次只处理这次数据指向的问题。

## 4. 后续功率任务：逐步增加实验能力

### 任务4：形成可重复的固定负载放电记录

前提是任务3已经取得可解释、可停止的通路响应。先完成相同短时工况的重复性检查；有需要时，再独立评估是否延长一次记录。

延长前明确本次总能量、负载实际散热、电芯退出边界和停止办法。25W标签不是实际安装下的连续散热证明，未经确认的温度模型也不能作为可靠的绝对温度保护。

交付：实物电芯电压变化、AFE原码/标称电流趋势、撤销后的恢复曲线。即使PWM暂时不能进入，这些仍是可交付的真实实验结果；它们不冒充占空比—电流关系或恒流控制结果。

### 任务5：受限PWM单点，再扩展局部开环（G03）

这一步新增MOS切换，必须单独准备，不能只把禁能编译开关打开。

我方工作：

1. 核对引脚到驱动的定义、有效电平、时钟/死区配置、继电器顺序和关断路径，结合已有资料和前面实测。现有配置中的DeadTime=0、Break禁用需要专项处理，不能因课件提到驱动内置死区就默认已经验证。
2. 选择本次真实反馈路径，验证更新周期、数据年龄、饱和与失效处理；AFE趋势测量不能自动替代快速过流/交越保护。
3. 补齐真实执行适配层与本地期限、数据有效性及相应保护。独立检查输入能量约束，不能仅靠串口、短时长或33Ω负载假定内部峰值受限。
4. 对本次单点明确电源、负载、占空比定义、起点、范围、期限及退出条件。课件0.90与禁能50mA不直接作为实物放行参数。
5. 先一个固定D，不接PI；有可解释响应后，再逐点、小范围改变D并保存数据。出现异常取消其余点。

三路直流源替代电池保留为备选，只有它能解决本次供能问题时才采用：需要核对串联/隔离、各路CC时的反向电压风险、回灌条件、输出电容和约18V板供电的其他供能路径。普通直流源不自动具备充电吸收能力。用户不需要现在改接线。

交付：固定工况表、D与实际CCR、时间对齐的真实响应、停止事件和局部D→I方向。若只能可靠观测电流趋势，就先交付D→原码/标称电流；补齐对应端口的电压测量与比例依据后再计算V/I/P，不能用负载电压乘电池电流冒充负载功率。

进入实际PWM的决定必须基于上述动作所需证据。没有示波器可以继续软件准备和适用的受限探索，但不能因此宣称死区、峰值或微秒级关断已验收。若现有条件无法约束MOS切换风险，就明确缺的是哪个参数、哪条供能路径或哪一种保护条件，先交付任务4的实物结果与本任务的实现；不承诺靠上位机一定能补齐这些物理证据。

### 任务6：先放电PI，再单独处理充电方向（G04）

可提前完成：统一单位、符号、Ts和Ki定义，实现限幅、抗积分饱和、给定斜坡、停机复位和旧样本拒绝，并用离线输入验证。不要复制讲义增益后直接带载。

接入真实放电PI的条件：任务5已取得本板局部反馈方向、可用运行范围与真实停止证据；反馈采样周期及延迟能够支持选定控制周期。只在新有效样本到达时更新控制，记录采样到CCR生效的时间。较慢AFE反馈不能被写成已实现100kHz快环。

交付：参数/工况、给定与反馈曲线、饱和恢复、启停与故障记录。自身反馈接近给定可以支持闭环功能，不单独证明真实电流精度；正式精度与高速动态验证另保留对应缺项。

充电作为独立方向准备：确认实际接收能量的电池及允许边界、充电电源和停机路径后，仍按“单点→局部开环方向→闭环”推进。放电成功不自动允许充电，三路普通直流源替代电池时不默认允许反向充电。不在本轮接充电电源。

这些任务服务真实实验，可与物理依赖未满足的步骤并行；不抢占首次实物记录的优先级，也不另起一套重复软件验证。

|---|---|---|---|
| 任务7：G05上位机与记录 | 复用已有CRC/request_id/重放处理；添加继电器单次业务、设备身份、质量状态、原码/估计值区分、曲线与一键导出 | 接入真实本地状态机；用实际动作核对请求/应用值、断连与恢复，重连不得重放运行命令 | 可运行记录工具、协议、原始收发和复算脚本 |

电流校准或容量依据缺失时，可以保留电压/原码响应数据及假设明确的电荷估计，不能把它们包装成SOC真值。脉冲捕获窗口之外的电流缺测不能静默当零；低频瞬时样本不能假装覆盖全部电荷。模型是否使用NPU也需实际执行证据。

## 6. 推进节奏与交付规则

1. **当前优先级：任务1 → 任务2 → 任务3。** 上位机先做本次记录必需部分；不先扩展界面、SOC模型或再次全量逆向HEX。
2. 每项任务开始时说明要回答的具体问题、采用的已有证据和本项新增工作；结束时交付源码/固件或数据与结论，并指定下一项。
3. 已有结果沿用明确的版本和适用范围；有新代码、失败或新疑点时才增加相应验证。
4. 每次实物运行单独保存manifest与raw/derived；失败不覆盖，采样/阈值/时长修改后建立新修订。不要为未运行计划生成通过记录。
5. 代理负责代码、参数来源核对、脚本、构建、下载和分析；用户仅在实际需要时配合BOOT/复位、可操作的端子/电池更换或电源设置，不让用户设计小引脚测量方案。
6. 需要用户配合时只提出本次必需且具体的动作；缺条件时写清会阻塞哪个实验，并继续不依赖它的任务。不能用笼统“缺标定”阻止所有工作，也不能把理论估算填成已确认硬限。

各阶段细则继续使用 [G03](prompts/G03-open-loop.md)、[G04](prompts/G04-pi-control.md)、[G05](prompts/G05-host-protocol.md)、[G06](prompts/G06-soc-dataset.md)、[G07](prompts/G07-model-deployment.md) 和 [验收规范](specs/acceptance.md)。本计划负责先后与条件，不改变课程要求或代替正式验收。

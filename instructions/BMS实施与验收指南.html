从“能读数”到“可信数据集”：BMS 实施与验收指南

你的主线是对的：先把测量做可信，再验证功率级，然后闭环控制，最后积累可用于 SOC 的数据。 需要修正的是：ADBMS 不会替你算好外接电路的电流和温度；占空比到功率不是固定的一条标定曲线；数据记录要从第一阶段开始；SOC 的参考依据需要单独建立。

本指南依据当前源码、课件、实验步骤、官方器件资料及你提供的其他工程 instructions。这里提出的是下一步执行方案，尚未完成任何硬件验收。

1. ADBMS 已经做了什么，MCU 还要算什么

可以把 ADBMS1818 理解为带内部 ADC、参考源和数字接口的多节电池监测前端。它完成模拟输入到数字码的转换，主控通过 SPI/对应通信链读寄存器。“已数字化”不等于“已变成安培和摄氏度”。 外接分流电阻、放大器、温度传感器与接线属于你的板子，芯片并不知道它们的完整参数。ADI 官方数据手册

现有 main.c 已在 BMS_ReadReg 中做 raw×0.0001，BMS_ReadSample 再做电流与 PT1000 换算。因此不能把这些全删掉，只留 SPI 读取。较合理的重构是：器件驱动保留通用命令和码值解释；板级测量统一存放通道、传感器模型和标定版本；控制与 SOC 放在上层。详见 测量分层。

2. 课件中的 STM32 ADC 主要在干什么

这个工程有两条采样链，而不是“STM32 ADC 再采一次 ADBMS 发来的数字量”。

电芯端子、温度分压、电流调理信号
    → ADBMS 内部 ADC → 寄存器 → SPI → 慢速监测、记录、保护输入

电流分流/放大器的模拟输出
    → STM32 ADC1 → 本周期电流 → PI → TIM1 → 驱动器 → MOSFET/电感
                                  ↑                    ↓
                                  └──── 实际电流反馈 ──┘

课件安排 STM32 ADC1 提供较快的电流反馈。TIM1 让 PWM 与采样具有确定的时序，PI 根据电流误差改占空比。它首先完成的是恒流控制 CC。

“第二层使用 ADC 追踪功率”这个说法不够准确。ADC 读的是引脚电压；经过电流测量电路和换算才得到电流。计算电池功率还需要对应的电池组电压：Pbat=Vpack×Ibat。这里三个 V 是三节单体电压，组电压需按实际串联关系求和，不能拿某一节电压乘整组电流就叫整组功率。

恒流时电池电压会变化，所以功率也会变化。以后若要恒功率 CP，可设计受限外环 Iref≈Pset/Vpack，再交给内层恒流环；必须限制电压过低、给定电流与动态响应。课件现有目标不能自动扩展为已经完成恒功率或最大功率点追踪。

课程提出的 100 kHz 控制目标对应 10µs 一个周期；1 Hz 上位机显示是另一种任务频率。不要把打印、阻塞 SPI、OLED 更新或模型推理放进每个电流控制中断。完整采样与计算时延要实际测量，不能只根据定时器配置认定达到 100 kHz。

电流精度不能只定百分比，零点附近需绝对误差要求。SOC 又对长期偏置更敏感：1Ah 电池若持续偏置1mA，积分1小时会产生0.1个百分点的SOC偏差。这说明“满足恒流实验”未必已经足够“高精度SOC数据”。具体预算应由容量、实验时长与目标误差倒推。

6. SOC 的“校正”应该拆成什么

第一步是测量标定；第二步是规定条件下的容量测量；第三步是给初始 SOC 一个有依据的锚点；第四步才是电流和时间积分；随后才能比较 SOC 估计器或训练模型。

充电为正、容量单位为 Ah、时间为秒时，可写：SOC[k]=SOC0+Σ(Ieffective·Δt)/(3600·Qref)。SOC 用0～1比例，乘100才是百分数；效率定义、容量口径、积分方式和缺口处理必须一致。上位机可以执行这些计算，但可信度来自测量与参考方法。

用同一个有偏置的板载电流产生 SOC 标签，又用它证明自己的 SOC 算法精确，会形成同源自证。可以用这样的数据做原型，但应称“代理标签”。更强的参考方案用独立校准的电流与时间链，并报告初始SOC和容量的不确定度。独立参考也不是没有误差的绝对真值。

HPPC/DST 等动态工况会暴露另一问题：1 Hz 的瞬时电流点不一定保留这一秒流过的电荷。可以保存更高频电流，或输出有明确时间窗的平均电流/累计电荷，并验证聚合算法。显示1Hz、SOC输出10Hz、控制100kHz是三个不同频率，重复输出旧值不能增加数据带宽。

训练集应先按电池/完整循环/实验段分组，再切时间窗口。课件的8:2划分是课程要求；若要宣称泛化精度，建议另设未用于调参的最终测试集，例如80%开发数据内部做训练/验证，20%锁定测试。不能先切高度重叠窗口再随机8:2，也不能用测试集拟合归一化或选择量化参数。详见 数据规范。

当前静态检查只能确认：模板在启动时执行一次 AFE 采样；MCU ADC/TIM 尚未 Start；PI 未接入运行链路；串口为回显示例；没有 SOC 训练或端侧模型实现。历史 README、旧日志、现成 HEX、源码中存在函数，都不能替代当前版本实测证据。

2. 所有阶段共用的边界

2.1 测量与换算必须分层

  1. AFE 传输层：SPI 命令/返回字节、长度、字节序、PEC、转换完成状态。
  2. AFE 码值层：电芯/AUX 结果按该器件规定的 raw × 0.0001 V 换算。ADBMS1818 自带 ADC，STM32 经 SPI 读数字结果，不再经过 MCU ADC。
  3. 板级物理量层：对传感电压应用实测零点、放大器增益、分流电阻、分压比例和温度模型，得到 A、V、℃。
  4. MCU 采样层：PA1 等模拟电压经 STM32 ADC，按实际参考电压、分辨率、过采样与标定换算；不能直接套 AFE 的码值比例。
  5. 应用层：只对有效、时间明确的测量执行显示、保护、PI、积分和记录。无效数据必须携带错误状态，不能伪装成有效的零。

MCU ADC 在本任务中的主要控制用途是电流反馈。计算 P=V×I 是测量运算，不等于已经实现恒功率控制、功率追踪或最大功率点跟踪。

2.2 端口、方向与功率定义

每个电压/电流字段必须声明测量位置、参考方向和单位：

  • Vbat / Ibat：电池端电压和电池端电流，课程约定 Ibat>0 为充电、Ibat<0 为放电。
  • Vload / Iload：负载端电压和负载端电流，正方向单独注明。
  • Vbus / Ibus：母线端电压和母线端电流，正方向单独注明。
  • Pbat=Vbat×Ibat、Pload=Vload×Iload 必须使用同一电气端口并时间对齐的数据。不能把 Vload×Ibat 当负载功率，也不能把 Vbat×Iload 当电池功率。
  • Boost 时 Vload/Rload 得到的是负载电流，通常不等于电池电流。能量损耗、动态储能和时间对齐也使两端功率不能无条件视为相等。
  • 单节电压、三节电压向量、整组电压应有不同字段，不能统一命名为含义不明的 V。

2.3 开环、闭环与保护

开环：D 由人工或测试前冻结的时间表给定，测量只用于记录、人工判断和保护。若根据测量持续自动调 D 以跟踪电流/电压目标，必须标作反馈闭环，不能作为开环验收证据。

保护：越限后撤销输出、锁存故障或进入明确停机态，可以存在于开环实验。不得以“自动调 D 维持电流上限”的持续反馈动作冒充纯开环。

停止路径优先：首次带载前，必须验证强制停止、复位默认态、继电器互锁与故障锁存；不能等 PI 调完再补停止功能。正常停止、故障快速关断、急停、通信失联分别定义动作与时限。上位机/MCP 请求超时不等于 PWM 已停止。

2.4 硬件参数唯一入口

实际硬件参数及限制只在 specs/hardware-profile.json 维护。本规范不建立第二套参数字典。null 表示未知，不表示无限制，也不表示零；课程值、允许测试范围和保护阈值分别处理。每次正式验收记录所用profile_id与文件哈希。

相应阶段还需确认的项目包括：过流触发阈值、输出关闭期限、继电器开断前电流条件、各方向起始D、驱动电压/有效死区、通信失联期限、最长运行时间。若profile尚未覆盖所需项，应先通过统一profile的版本变更补齐，不在验收报告或脚本内静默增加另一套默认值。

H 项须附实物/规格/原理图/台架依据和确认者。课程要求的测试点若超出已确认硬限，应标为未执行并处理条件冲突，不能提高硬限，也不能以另一个测试点代替后写成原要求通过。

G02：无功率 PWM、采样时序与强制停止

前置

  • G00通过，G01的采样路径/量纲已验证；功率能量路径未接入或处于冻结的禁能测试状态。

方法

  1. 固定50% D，测PA9/CH2与PF7/CH2N频率和互补关系；改变CCR，核对实际D定义。
  2. 核验实际TIM时钟、PSC、ARR、RCR、极性、空闲态、预装载和启动顺序。
  3. 按台架方法观测驱动输出的幅度、死区及交越；确认“无同时导通”由实际输出证明。
  4. 仪表化标记TRGO、ADC完成/回调、CCR写入及生效时刻；统计触发、完成、overrun和丢周期。
  5. 验证手动强制STOP、故障输入、软件复位、启动失败的输出禁能、继电器互锁和锁存状态。未接功率时可以用可控注入验证逻辑；不必制造真实过流故障。

  • C：100kHz互补PWM；50%基础验证；中心对齐、RCR=1、ADC同步触发目标。[C-P08][C-P10][C-D01]
  • E/draft：频率相对目标误差≤1%；50%测试点占空比误差≤0.5个百分点。实际允差应结合时钟与仪器冻结。

G03：受限带载开环

前置

  • G01、G02通过，尤其强制停止已经验证；带载所需H硬限全部有值和依据。
  • 固定电池、负载、母线、散热、测试时长、允许D范围和起始点。D=0.90不是所有模式通用的安全保证。

方法

  1. 禁止PI及其他追踪反馈更新D；D来自人工或预先冻结的时间表。
  2. 先验证放电路径；每个点记录D命令/实际CCR/PWM、Vbat/Ibat、Vload/Iload、Vbus/Ibus中实际可测的字段，以及温度、状态、输入条件。
  3. 按课程扫描点与已确认硬限的交集执行。每点的稳定条件、记录窗口、退出条件预先确定；越限立即走停止路径，不为凑齐表格继续扫描。
  4. 用上管D定义比较：Boost理想稳态 Vout≈Vin/D；充电Buck的电压比关系另行验证。解释损耗、CCM/DCM、负载温升和电池电压变化。
  5. 从独立实测判断局部 D→Ibat 的符号，为G04反馈方向提供证据。
  6. 如需宣告双向功率级完成，补充充电路径的受限开环证据；单向结果不替代双向。

指标

  • C：上管D=0.90、0.80、0.70、0.60、0.50、0.40，10个百分点步进；记录曲线并比较理论；开环先于闭环。[C-P09][C-D02]
  • C-条件约束：PPT在33Ω负载条件下写放电电流限定0.5～0.8A；实际验收须明确电流所在端口，并与H限制核对，不能直接套到Iload或Ibat的另一端。[C-P09]
  • E/draft：每点条件稳定后保留至少2s同步记录；稳态判据由输入漂移和电流/电压变化量冻结。只读一次万用表值不足以验收动态或保护。
  • E/draft：实际D在允许范围内；实测趋势与本板D定义相容；所有理论偏差有数据解释。课程未给出统一理论误差百分比，不擅自设为课程硬线。
  • H：每方向安全起始D、最大电流/电压/负载功率、温度、持续时间及中止条件。

证据

逐点CSV、台架与负载条件、D-V/D-I曲线、端口定义、理论/损耗计算、代表性驱动与电流波形、未执行点及原因、停止事件。

失败回退

测量反馈自动改D却标开环、跨端混算功率、未知实际占空比、趋势不符且无解释、越限继续运行，均不得通过。保持停机，按问题退回G01测量、G02输出或G00硬件边界。

G04：PI 恒流、故障与换向

前置

  • G03通过，反馈方向已由实测确定；统一 pi.c/pi.h、PI状态和接口；采样有效性与STOP优先级已验证。
  • 固定Kp、Ki、Ts、限幅、抗饱和方式、初始D、斜坡、模式状态机及故障策略。讲义参数不是免测试的默认值。

方法

  1. 接通新ADC结果→物理电流→误差→PI→限幅→CCR，检查 e=Iref−Imeas 与实测对象增益形成负反馈。
  2. 分别测试充电与放电的启动、小给定变化、保持、允许扰动、饱和/解除、停止和再启动。
  3. 先停再换向：撤销输出并确认电流已衰减到冻结条件，再执行继电器切换和重启；互锁任何时刻不得被远程命令绕过。
  4. 正常停机与故障快速关断分别验证，记录电流衰减、输出关闭、继电器动作和锁存。等待20/100ms仅是讲义示例，不能替代实测衰减条件。
  5. 用高时间分辨率采集Iref/Imeas/D/积分/状态；用独立参考电流确认实际误差。
  6. 测量转换、等待、ISR计算及CCR生效的最坏延迟，在OLED/UART等同时运行时重复。1Hz曲线不能验收超调、纹波、停止瞬态或10µs周期执行。

指标

  • C：±0.5A分别验收稳态误差＜5%，即在这两个指定工况下 |Iactual−Iref| < 0.025 A；这不是所有给定的固定25mA容差，更不是过流保护阈值。[C-D11]
  • E/draft，参考不确定度护栏：稳态窗口内使用独立参考电流，要求 |mean(Ireference)−Iref| + U95 < 0.025 A才判pass。U95应包含参考仪器、换算/位置/时序比较等适用分量，避免重复计入。有效证据的不确定度区间与边界相交时判inconclusive；明确整体超出容差时判fail。不确定度来源不足时不能只看中心值宣告通过。

测量的分层、换算与标定

两条测量路径

慢速监测：电芯端电压 / 电流调理电压 / 温度分压 → ADBMS 内部 ADC → 寄存器数字码 → SPI → MCU。

快速反馈：分流电阻和放大器输出 → STM32 ADC1 → 当前控制周期的电流 → PI → TIM1 PWM。两条电流路径是否共用同一模拟节点，要用原理图和通断测量确认；各自仍需标定。共用前端时，两路一致不等于独立准确。

职责表

层 应完成什么 不在这一层实现什么
外设/HAL 时钟、GPIO、SPI 传输、ADC 触发/DMA、TIM PWM 电池 SOC、温度传感器模型
芯片驱动 唤醒、转换命令、完成确认、寄存器、PEC、raw 解码、器件规定缩放 分流阻值、传感器型号、PI 参数

控制/保护 可信且及时的 I 与限值检查、PI、状态机、停止和换向 SPI 字节拼接、CSV 格式

BSP 是组织方式，不是硬性标准：板级测量可以放在 BSP/measurement，也可以独立目录。关键是器件通用驱动不绑定某块板的系数。当前 BMS_ReadReg/BMS_ReadSample 在 main.c 中，建议后续迁出，但本轮未改源码。

哪些公式要写

  1. ADBMS 电芯/AUX 结果：raw = lo | (hi << 8)，按对应寄存器定义 V = raw × 0.0001 V。不再套 STM32 的 Vref / 4096。不是所有 ADBMS 寄存器都表示普通电压，状态、阈值或特殊测量按各自定义处理。依据：ADI 数据手册。
  2. STM32 ADC：若确认 12 位、右对齐且没有改变输出尺度的累加/移位，理想量化步长为 Vref/4096。工程用 V=a·code+b 或 I=aI·code+bI 的标定关系；端点拟合有时写 4095，必须明示约定，不在同一链混用。过采样后的最终输出位宽/移位、参考电压、校准流程均须核对。
  3. 电流：Vsense = Vzero + s·G·Rshunt·I，故 I=(Vsense−Vzero)/(s·G·Rshunt)；s 为接线符号。实际可直接拟合 I=a·raw+b。芯片不知道外接分流阻值与电流方向，因此这部分由板级软件负责。
  4. 温度：只有确认“上拉 R_up 接 Vexc、传感器接地”的拓扑才用 R=R_up·V/(Vexc−V)；当前代码示范 PT1000 线性近似 T≈(R/R0−1)/α。NTC 需另一套模型；PT1000 宽温区用适合其型号的曲线/查表。系数与适用温区必须记录，不混用教材图示和实装型号。
  5. 功率、能量、SOC：在应用层计算。Pbat=Vpack·Ibat，充电正、放电负；输出端 Pout=Vout·Iout。不同端口的 V、I 不能直接相乘当某端功率。瞬态平均功率为 mean(v·i)，未必等于 mean(v)·mean(i)。

不必用软件重做 ADBMS 内部 ADC 调制、数字滤波、硬件转换；但仍要选择模式、等待完成、读取并检查质量。芯片内部温度也不能替代电池表面温度。

标定流程

先确认量程/电路，再记录 raw 与独立参考，在覆盖工作范围的多个点拟合；独立重采其他点验证；最后检查零点回测、重复性、升降扫和温漂。不要只看 R²。

零点、参考电压、电子标定与整机校准不同：STM32 内部 ADC 自校准不能消除外部放大器/分流/接线误差；一条 ADBMS 电流通道标定也不能替另一条 STM32 通道出证。

正式误差判断应包含参考及方法的不确定度。建议统一用 |误差| + U95 ≤ 容差 才判 pass；若 |误差| − U95 > 容差 则 fail；覆盖边界时 inconclusive。课程严格“小于”指标应相应使用严格不等式。拟合用数据与独立验证用数据分别列 ID。具体容差见 acceptance，不把分辨率、芯片典型精度或闭环误差当测量精度。

建议预先约定三态保护带规则，保存各验证点结果：

e = I_DUT − I_reference
Ue = 本次误差比较的扩展不确定度
通过：     |e| + Ue ≤ MPE
不通过：   |e| − Ue > MPE
无法判定：其余情况

Ue不等于显示分辨率。U=k×uc须记录覆盖因子；k=2不总是严格95%覆盖。“无法判定”不得算作通过。

5. SOC 标签的口径与不确定度

统一符号：流向电池为正，充电为正、放电为负。SOC保存为0～1；百分数仅作显示。C_N 单位Ah、Δt单位秒。

q[k]   = q[k−1] + I_effective[k] × Δt[k] / 3600
SOC[k] = SOC0 + q[k] / C_N

C_N注明铭牌或已测容量。正式标签优先用对应电池、温度、倍率及截止条件下的已测容量，保存记录ID、日期和不确定度；不能为使终点归零而事后改容量。

SOC0记录锚定依据及不确定度，例如定义充电终止/静置条件后的满充锚点。单次端电压不等于精确SOC；OCV映射须匹配电池、温度和静置条件。

效率口径写进 efficiency_model。例如充电时使用 I_effective=ηc·I；放电是否取 I 或另设效率，取决于参考容量的定义。不得把容量测量中已体现的损失再次重复计算。效率取1可以作为明确标注、带适用范围的近似，不代表已测得100%效率。

参考SOC不能由同一误差自证

正式精度评价优先使用独立校准的外部电流和已确认的计时基准建立参考SOC，板载电流作为输入或待测对象。参考SOC也有不确定度，不称绝对真值。

若标签来自同一板载电流的安时积分，标记：

label_source = same_sensor_coulomb_counting
label_grade = proxy

代理标签可用于原型；拟合误差小或同源积分一致都不证明真实SOC精度，共同偏置会同时污染输入和标签。

标签保存SOC值、有效性/等级/版本、初值锚点、容量记录、电流源、标定ID、效率模型和不确定度。

未知电流缺口不得按零积分。独立参考补齐须注明来源；否则评估误差界限，无法界定时暂停后续标签有效性，直到可信锚点。保留未裁剪SOC与越界标志，不用0～1裁剪隐藏漂移。

示例：1 Ah电池持续偏置1 mA，一小时累积0.1个百分点SOC偏差；不是允许指标。预算应包括零偏、增益、时钟、效率、初值和容量，共同偏置不能作为独立噪声平均掉。

相关项需保留协方差或采用有依据的保守界限，区分共同偏置、增益与重复性。INL 原始研究

2. 一份工作卡保留五个问题

  1. 问题与范围：本次要解决什么，对应哪个需求；哪些上游事实已经确认。
  2. 设计与条件：用哪块板、哪些输入、变量、工况和方法验证；单位和输出位置是什么。
  3. 判据与版本：什么条件算通过、失败或证据不足；正式运行前固定哪些文件。
  4. 执行步骤：具体做什么、前置条件是什么、产物和检查点在哪里。
  5. 结果与结论：实际执行了什么、原始证据在哪里、按哪版规则得到什么结论，还有什么未覆盖。

3. 探索与正式验收分开

**探索（exploratory）**用于核对 ADC、排查接线、分析串口和调节 PI。允许在观察后调整候选方案；记录重要配置变化和失败，结论写成“观察”“候选”或“待复验”。探索使用过的数据不能事后改名为独立正式验收数据。探索仍须遵守实际硬件边界。

**正式验收（confirmatory）**用于回答事先明确的需求。先准备可执行候选、输入、参考方法和验收规则，再在正式运行前固定其身份。冻结不要求尚未写出的代码提前存在，也不阻止前期编译、调试和测量准备。

正式验收需冻结：判据版本、工况及输入、配置、待测代码/固件、测量与结果计算方法。冻结清单写入实际时间和文件哈希；清单自身的 SHA-256 记录在工作卡中，不把自身哈希写回清单造成循环。没有 Git 时可使用源码清单和哈希，不能伪填提交号。

正式结果产生后改变固件、参数、工况或阈值，应保留旧版本，建立新修订及新 run ID，并说明原因。目标、硬件或方法发生实质变化时再新开工作卡。不得修改旧结果来适配新规则，不删除失败来制造连续通过；未运行的项目仍记为未运行。

4. 状态、判定与证据范围分开

字段 含义 建议值
status 工作推进到哪里 not_started / in_progress / blocked / complete / skipped
verdict 正式验收得出什么结果 null / pass / fail / inconclusive / invalid
evidence_scope 本次实际证据覆盖什么 static / build / simulation / bench / release_boot 的列表

这些证据范围不是自动递升的等级。编译通过不证明电流闭环正常，模拟通过不证明实际板卡通过，Debug 能运行不证明 Release 断电重启正常。

  • complete + fail 表示验收已执行完毕且被测对象未通过，属于有效结果。
  • blocked + null 表示缺少前置资料或条件，尚无最终判定。必须写明阻塞事实及所需输入。
  • inconclusive 表示实际证据不足以按规则完成判定；未测项目不能默认通过。
  • invalid 用于检验过程失效，例如原始数据损坏或参考仪器设置使记录无法解释。有效测量发现超调、误差超限或故障动作失效应判 fail，不能借 invalid 排除产品失败。
  • skipped 需有不适用或不启用的理由，不等于通过。
  • 探索工作可以完成并留下观察，但不把它登记为正式验收 pass。

运行身份、原始数据和判定留在工作卡及对应证据目录；STATUS 只摘要和指向它们。若汇总与原始证据冲突，先核查事实并修正汇总，不能覆盖原始文件。

5. BMS 证据链的具体落点

最短链路是：需求 ID → 验收版本 → run ID → 实际源码/固件与工况 → 原始记录 → 计算方法 → 判定。

每次适用运行记录源码版本或清单哈希、未提交改动状态、Debug/Release target、编译器/设备包版本、生成固件哈希和构建日志。实际烧录后再补写镜像哈希、目标地址与下载校验结果；计划烧录信息不能冒充执行记录。

台架记录另外包含板型/板号、接线版本、仪器及量程、采样与控制周期、换算/标定系数、工况、开始结束时间、异常和退出原因。原始串口或仪器文件与派生 CSV、图表和统计分开保存，失败复测使用新 ID 并指向旧 run。

当前工程优先建立源码、IOC、说明文档、Debug/Release 产物之间的对应关系。旧文档或旧构建日志只证明其所覆盖的历史版本；未经本次验证的现象明确标为历史报告或待复现。

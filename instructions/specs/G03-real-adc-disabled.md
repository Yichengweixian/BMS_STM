# G03 真实 ADC 禁能诊断与扫描

固件 `g03-adc-r4`。新增真实ADC分支运行时，PWM引脚、TIM1和继电器保持禁能；既有G02仍可运行无引脚输出的内部定时采样。编译时拒绝与 `G02_ALLOW_PIN_OUTPUT=1` 共存。保留既有 G02 和合成 G03 分支，新增独立的真实 ADC 电流诊断分支。真实电芯/温度的整套 G03 功率保护尚未接通，本版不提供功率使能命令。

## 1008 与 2048 的对照

冷启动不自动执行 ADC 校准，以保留校准前证据。命令21依次选0、1、2、3、4、5，每个配置保存64个原码、最小/最大/总和及12项寄存器：CFGR1、CFGR2、CALFACT、DIFSEL、GCOMP、OFR1、SQR1、SMPR1、PCSEL、CR、公共CCR、GPIOA MODER。

| profile | 过采样 | 本次执行内部自校准 |
|---|---|---|
| 0 | 2次、右移1位 | 否 |
| 1 | 关闭 | 否 |
| 2 | 关闭 | 是 |
| 3 | 2次、右移1位 | 是 |
| 4 | 关闭；持续ADEN，每1ms触发 | 是 |
| 5 | 2次、右移1位；持续ADEN，每1ms触发 | 是 |

自校准状态0=本次启动未执行、1=成功、2=失败。执行过自校准后再选0/1不会恢复芯片复位校准因子，状态仍如实报告；因此“前后对照”必须在一次新启动先0/1再2/3。诊断结束保留最后选择的采样配置。自校准是ADC内部偏移处理，不是实物电流斜率或方向标定。G01在配置变化后立即输出新元数据。

已核对本地HAL：`Oversampling.Ratio=2` 写入的是 `(2-1)<<OVSR`，搭配右移1确为平均，源码没有额外除2。旧HEX有ADC校准流程，当前旧镜像未调用。最终差异原因须由新镜像实板对照判定，不能用模拟测试中的输入变化当作实板结论。

## 换算与零点的证据边界

`nominal_current.h`移用独立HEX的K=1.3266666730244954 A/V、MCU LSB=float32(1.8/4095)、AFE LSB=float32(0.0001)。来源哈希与地址见 `evidence/runs/20261031-prebuilt-formula-audit`；模型ID为 `hex-dd44fae1-nominal-v1`。

G01两路电流均以0.9V标称零点输出estimate，physical_valid恒0，physical_value/reference留空；原码不改写。AFE保留线性小值，不复制旧HEX的约0.8mA显示死区。

新增ADC扫描仅接受profile4/5的静态基线：全部64个原码均保存，前16个作为禁能启动观测，后48个的均值作为“假定零电流基线”，精度为千分之一原码；必须内部自校准成功、稳定段读数不近轨、峰峰值≤32码。profile0—3保留每次Start/Stop与HAL_Delay(1)的历史对照，不允许作为新扫描基线。当前HAL会给Delay参数增加一个tick，因此profile4/5使用HAL_Delay(0)到下一个1ms节拍，与监控触发周期匹配。它只验证禁能情况下的相对换算和软件保护，不证明真实零电流或模拟链斜率。

阈值50mA为禁能测试夹具值，不是电池/转换器安全限值。窗口按标称系数逆算，低边界向上取整、高边界向下取整；任一边界越出1—4094、窗口无宽度或输入非法则拒绝，绝不钳位后继续运行。hardware-profile的未知实物限值继续为null。

## 本地路径与扫描记录

显式START独占ADC1，先在完全禁能状态进行64次持续ADEN的预采样，保存全部原码；稳定段必须仍落在已接受的窗口中，不重新移动零点。预采样失败、漂移或不稳定均拒绝扫描、撤销配置并锁存。该阶段不属于功率保护且不允许实际输出。ADC保持使能，清除预采样的标志后开启AWD中断并启动监控；随后SysTick每1ms发软件触发，ISR读取真实原码。IRQ不打印；主机不承担停止判定。ADC看门狗AWD1选择通道1，无连续样本过滤；AWD/OVR事件进入IRQ后首先执行既有寄存器禁能，再锁存事件。原码窗口比较提供另一条软件检查。SysTick发现超过5ms无完成、800ms无新心跳、期限到达或输出位异常时本地停止。数值均为禁能诊断期限，未测得电气关断时延。

扫描期限100—2000ms，分5点：影子CCR=1800、1700、1600、1500、1400，对应ARR2000下0.90至0.70。不写实际TIM CCR、不启动TIM、不闭合继电器，因此这不是D→I功率特性测量。故障取消余下扫点，无自动重试/恢复。G02、合成G03与新增ADC分支互斥；共同STOP(op13或旧op2)一并撤销它们。

轨迹为256项环形记录，保存seq、HAL毫秒、DWT周期、原码、相对标称电流uA、影子CCR、事件与故障。每10次完成记一次，另记首次样本、START、换点、STOP和故障。written/overwritten显式报告；序号过旧拒绝读取。START及无有效原码时uA=INT32_MIN；无EOC的故障事件保留最后采样值，不代表新样本。只在停止并释放ADC后读取轨迹。单次正常2秒扫描可容纳全程记录；不保证有ADC故障之后的采样，因为故障即停止采集。

本地关断后在主循环执行HAL清理；清理失败保持ADC占有和故障，阻止G01/G02抢用。CLEAR不启动并撤销配置。CPU停摆/关中断时仍不保证服务期限，本版不是独立硬件看门狗。

## 串口

沿用 `G02,id,op,arg*CRC16`，请求ID/CRC/重复缓存规则不变。身份为g03-adc-r4，ADC响应使用独立帧，合成G03响应仍标synthetic=1。ADC状态帧power_capable=0、physical_valid=0。

| op | 参数 | 用途 |
|---|---|---|
| 20 | 0 | 状态#G3A |
| 21 | 0—5 / 6 | 0—5执行配置对照；6只读最近诊断或启动预采样，#G3D含64原码及寄存器 |
| 22 | 0 | 接受稳定静态基线，选择50mA诊断窗口 |
| 23 | mA | 停机修改诊断窗口，量程外拒绝 |
| 24 | 100—2000ms | 启动真实采样、五点影子扫描 |
| 25 | 0 | 新ID心跳；重复请求不续期 |
| 26 | 0 | 停止真实ADC分支 |
| 27 | 0 | 清故障、撤销配置，不启动 |
| 28 | seq | 停机读取轨迹#G3T |
| 29 | 1/2 | 静态读数之外的两侧AWD测试窗口 |

op29只改变ADC阈值，保留实际静态原码：1将窗口移到静态值上方，2移到下方，用真实ADC看门狗事件验证中断链。probe字段标记测试，不能报告为真实电流超过50mA。采样/扫描期间不支持修改窗口、校准、换配置或读轨迹。

状态/诊断/轨迹字段表以 `scripts/g03/adc_diagnostics.py` 为准。脚本保存未经清理的串口、请求事件、全部解析响应和逐场景CSV；检测重启、未知身份、CRC错误或输出位异常即终止并尝试STOP。

## 验证命令

```
python scripts/g03/run_adc_checks.py --out evidence/runs/<new>/adc-checks
python scripts/g03/adc_diagnostics.py --port COM9 --out evidence/runs/<new>/board
```

本地测试包含生产C核心、真实适配层、UART联调和Python解析；寄存器/HAL由模型驱动，不替代芯片行为。实板脚本覆盖六配置、量程拒绝、五点记录、双侧AWD测试、失联、重放心跳、停止/清理；之后单独回归G02、合成G03和G01恢复。

继续跳过用户无法完成的探头及外部标定；禁能验证不证明功率级波形、实际限流精度、驱动死区、继电器隔离或真实开环充放电。

## 实现修订与失败保留

r1的首条诊断响应曾触发2KiB栈溢出；r2将1024字节响应缓冲改为主循环常驻并新增栈帧检查。r2每次转换启停的64点包含明显启动偏移，稳定性拒绝基线，未绕过。

r3新增持续使能与明确启动段，但预采样的HAL_Delay(1)实际为两tick，与1ms监控存在节拍差异。实板第二个样本触发AWD和原码比较，故障96锁存；这验证了真实越窗退出，同时是正常扫描失败。r4统一持续采样节拍；原判据32码和50mA诊断窗口未放宽。各修订的原始数据、失败与固件身份独立保留。

1008/2048不是已确认的两倍比例误差；过采样、自校准、采样时间、持续使能和片内参考对照的实测结果统一见最新run工作卡。即使禁能扫描通过，也不建立真实电流零点、方向或斜率。

# 开环充放电前的上位机验证

本轮按用户要求跳过需要探头、接线夹具和硬件标定的工作；不要求将电池改成三路电源或拆电池。使用已验证的禁能固件完成内部采样、协议异常、停止/故障及记录链测试。普通直流电源不能据此作为充电吸收端。

## 已提供的工具

| 工具 | 用途 |
|---|---|
| `scripts/g02/run_checks.py --out <新目录>` | 生产状态机、寄存器端口、串口及14项Python上位机/工况测试 |
| `scripts/g02/extended_diagnostics.py --port COM9 --out <新目录>` | 13组真实板端禁能测试；要求g02-host-r2，识别失败不启动 |
| `scripts/g01/g01_capture.py --port COM9 --seconds 60 --firmware-sha256 <实际HEX哈希> --out <新目录>` | 九通道只读记录、身份、质量、序号、原始数据 |
| `scripts/g02/prepower_plan.py --profile instructions/specs/hardware-profile.json --plan scripts/g02/open-loop-plan.template.json --out <新目录>` | 输出未知硬限/证据缺项；仅在给定合法参数时编译和模拟固定占空比表，无串口执行能力 |

串口一次只有一个控制者。每次运行使用新目录；原始串口、收发事件、派生CSV和结果包含哈希，失败也保留。旧r1记录可由解析器读取，扩展板测工具要求修复后的r2。现成课程上位机exe没有被臆定为兼容本协议；本轮提供的是有源码的命令行上位机。

## 重要修复和语义

`g02-host-r1`在停机时拒绝COMPARE，却先修改了共享的下一次启动参数。r2在命令返回非OK时恢复原compare/window参数；回归先复现失败，再验证修复，实板检查确认被拒的CCR不影响随后START。

同一最新请求的完全重复返回原命令结果，不重新执行；相同id不同参数返回8，过期id返回7。一个业务请求未完成时不排队未来启动；COMPARE/STOP/FAULT可以取代等待响应，start_id关联当前采样。重连只查询，不重放。测试工具识别到复位/超时/坏CRC会终止本轮，识别固件后异常会尝试STOP；没有自动清锁存和重启。

内部采样的本地窗口为1—10000ms，主循环执行到期停止。关闭主机句柄测试验证主机不发送STOP时窗口仍收尾；**没有物理拔USB，也没有新增独立通信失联看门狗**。主循环不服务时窗口不能保证停止；该结果不能用于带功率失联保护验收。

运行中不发送统计，停止后才能读取；因此收发往返时间不是真实停止延迟。CCR1/1000/1999仅检查内部合法边界和更新观察，均无引脚输出，不是允许带载的占空比范围。重复窗口的计数为软件服务次数，不是独立硬件事件计数；不能将名义周期与统计差值事后设成合格容差。

## 固定工况与功率分析准备

`open-loop-plan.template.json`保留未知duty/duration为null；唯一实物限值来源仍为hardware-profile。准备工具检查方向、固定模式、有限数值、持续时间、量化后CCR及总时间。离散模拟支持STOP/故障取消后续工况并保留停机/锁存，不模拟转换器、电流或热行为。14项测试里的电压、电流和限值全部是显式合成夹具，不写入实物profile。

`port_power()`只接受带有效物理量、标定身份、端口、会话、时间和参考方向的数据。异端口、异会话、未标定、无效、时间偏差过大或非有限值会拒绝。当前G01原码未标定，不能用于宣称真实充放电功率或局部D→I方向。

## 本轮明确跳过的验证

- MCU PWM引脚、驱动及Vgs波形，电平、互补、死区、实际采样相位和真实停止期限：需探头与合适测点。
- 电压/电流/温度的物理标定、同支路参考与方向确认：需独立参考及适用夹具。
- 冷启动重复、物理拔线、CPU复位电气行为：本轮只验证用户正常BOOT复位启动，未把软件回放当实物验证。
- 继电器实际极性/触点隔离、带载失联和越限停止：需要已确认的功率路径与硬限，不能由内部命令测试推断。
- 受限开环充放电、带功率换向和PI：没有执行。准备工具没有功率执行接口，G02编译门仍关闭。

这些缺项不阻塞独立软件准备，也不会因跳过而变成通过。实际阶段进度和证据入口统一见[STATUS](../STATUS.md)。

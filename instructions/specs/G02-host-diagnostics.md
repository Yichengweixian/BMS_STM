# G02 上位机内部诊断

版本补充：`g02-host-r2`修复拒绝COMPARE/START后共享参数的副作用，帧结构和命令号不变；报告版本标记改为r2。新版支持的扩展工具和验证边界见[开环前上位机验证](prepower-host-validation.md)。旧r1日志保持原版本，不覆盖。

用户明确当前不能配合PWM探测、示波器或硬件标定。G02后续采用串口自动诊断；不要求更换电池为三路源、拆电池测空载充电电压或探测芯片细脚。沿用当前测量，不开展能量传输。三路普通直流源不能因用作G01电压激励就被当作可承受充电回灌的电池。

## 可执行范围

固件 `g02-host-r1` 增加独立G02串口入口；默认仍为G01原码流。上位机可启动内部TIM1→ADC1采样，做CCR预装载观察、STOP、软件故障注入、锁存拒绝重启及清除。PA9/PF7保持GPIO LOW，MOE/CCER为0，继电器保持LOW命令。串口协议没有PINS或继电器操作，两个target的编译门均关闭。

它支持内部寄存器/ISR计数及状态机观察；不证明引脚频率/幅度、驱动互补/死区、MOS栅源电压、实际触点隔离或物理停止期限。已有 `G02-pwm-timing.md` 的电气判定边界继续有效。无示波器条件下这些结果保留null；软件与台架内部计数不能代替G02.4或放行G03带载。

## 上位机运行

```powershell
python scripts/g02/host_diagnostics.py --port COM9 --out evidence/runs/<新run>/host-session
```

一个串口只有一个所有者，运行此工具时不能同时运行G01记录器。工具先查询并核对固件响应及pins_gate=0；失败即停止，不盲目发送启动序列。测试顺序：1秒采样；10秒上限窗口内CCR1500及STOP；故障注入、锁存后拒绝Start、Clear后保持停机；10秒连续内部采样。所有原始接收字节、请求/响应、CRC、软件状态和错误保存。测试失败不自动清锁存/重试启动；识别固件后出错会尝试STOP并保存其响应。设备复位使当前运行终止。默认10秒自动停止仍是MCU主循环措施，不是独立硬件看门狗。

## 帧与处理

请求为ASCII `G02,id,op,arg*CRC16\n`。CRC为CCITT-FALSE，初值FFFF、多项式1021，覆盖星号前全部ASCII；四位大写十六进制。id为1至UINT32_MAX，每次新请求严格递增；仅重复最新id且payload完全相同可取既有结果，不再执行。旧id拒绝(result7)，同id不同payload拒绝(result8)。一次只发送一个未完成业务请求；在采样运行期间可用更新id的COMPARE/STOP/FAULT取代等待请求，响应的start_id保留对应采样身份。跨id回绕需在明确复位后建立新会话，工具不自动复位。

| op | arg | 动作 |
|---|---|---|
| 0 | 0 | 状态查询 |
| 1 | 1—10000 ms | 内部采样，输出保持关闭 |
| 2 | 0 | STOP |
| 3 | 0 | 软件故障注入 |
| 4 | 0 | 清故障，仅回停机 |
| 5 | 1—1999 | CCR预装载请求；只在运行中有效 |

UART ISR只把字节放入256字节环形队列，不打印、不启动采样；主循环处理完整LF帧。超长/非法字符/坏CRC拒绝，RX错误或溢出后丢弃至下一LF重新同步。响应以 `#G02,g02-host-r1,...*CRC16` 开头，字段顺序以 `host_diagnostics.py:FIELDS` 为准；包含请求id/返回码/start_id、状态/故障/ADC占有、实际时钟、开始/停止tick、UEV/ADC服务次数、OVR/ADC错误、ISR开销与迟到计数、CCR请求/观察、软件停止区间、协议错误及输出编译门。

采样期间不格式化或发送响应；请求结果延迟到停止/故障后返回。因此不能把UART往返时间当作STOP物理延迟。CRC及队列管理也不是完整G05业务协议，本阶段不实现功率命令。

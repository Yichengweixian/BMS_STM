# 执行与变更规则

## 最短证据链

`需求 ID → 测试/工作卡 ID → 固定判据与版本 → run_id → 原始数据 → 复算指标 → 结果 → 允许的结论`

每个正式 run 保存 `manifest.json`，证据建议存于项目根 `evidence/runs/<run_id>/`：`raw/` 放未经覆盖的串口、仪器、示波器导出；`derived/` 放带处理版本的 CSV、图与指标；`result.json` 写结果、规则版本和解释。这里仅定义未来路径，未生成任何实验数据。

## 探索与正式验收

- 探索用于调参数、发现硬件与配置问题。记录重要配置、异常和原始数据，允许修改方案，不要求在尚无可测实现时就冻结代码。
- 正式验收前，待测固件、接线、仪器、配置、工况、指标、通过线和处理代码都已准备好。用 Git 提交或源码文件清单 SHA-256 固定身份；有未提交改动就保存 diff/文件清单，不用旧 commit 假装完整身份。
- 冻结后改变上述任一影响结果的内容，要建立新修订与新 run。原失败保留。阈值修改说明工程原因，不能用“刚好让结果通过”作依据。
- 调 PI、选模型、决定滤波器时看过的数据不能再冒充独立验证集。修复后重新验证受影响部分，无关项目可沿用有明确依赖说明的证据。

## 状态和结论分开

`status`: `not_started | in_progress | blocked | complete | skipped`。

`verdict`: `null | pass | fail | inconclusive | invalid`。

`evidence_scope`: `static | build | simulation | bench | release_boot` 的列表，不是自动递升的等级。

- `complete + fail`：测完且明确未达到要求，正常保留。
- `blocked + null`：缺条件，尚未取得可判定结果；只阻塞依赖该条件的任务。
- `invalid`：实验本身无法解释，例如参考接错或采集文件损坏。有效实验中的超调、超时、保护失效是 fail，不能改称 invalid。
- `inconclusive`：证据有效但不够判定，如误差与参考不确定度覆盖验收边界。
- 结构检查、编译、仿真、台架、断电再启动分别报告，不能彼此替代。

## 标准来源与冻结

统一标签：C=课程明确要求；E=工程建议，待正式冻结；H=硬件或需求待确认。芯片数据手册事实注明具体来源，不能把芯片指标当整机验收线。

先确定边界，再定指标。额定值、推荐运行范围、允许测试范围与保护触发阈值分开；绝对最大额定值不是运行目标。硬件未知参数保留 null，禁止用 0 或示范数值冒充确认。

## 变更影响

| 变更 | 至少重新检查 |
|---|---|
| 分流、增益、参考电压、ADC 模式、温度探头或接线 | 对应通道标定与独立验证；使用它的保护与控制；受影响 SOC 标签/数据版本 |
| PWM 极性、时钟、死区、采样相位、PI 或控制周期 | PWM、时序、受限开环、闭环和故障退出 |
| 串口协议、日志格式、时间戳处理 | 解析、丢包/重启检测、积分重放与数据字典 |
| SOC 初值、容量、效率或标签处理 | 标签版本与模型重评；不覆盖原 raw |
| 仅文字显示或注释 | 与变化相称的检查，不新建整套实验 |

## 代理和未来 MCP

代理按当前用户授权修改、构建、分析与回放，不照搬其他工程的模型路由。工具结果要返回实际执行范围、文件路径、版本、退出码和证据，不用“调用成功”代替实验通过。

未来可逐步封装 `build_firmware`、`capture_telemetry`、`replay_run`、`evaluate_run`。先用模拟器和既有原始数据闭环；接入下载器、仪器和带载控制时，按已确认的硬件 profile、运行状态机及用户授权限定动作。一个串口只有一个控制所有者，写命令带 request_id；重试需要明确幂等语义。MCP 不承担 MCU 的微秒级 PI 控制和硬件保护。

不为每次编译、文档或离线分析重复询问许可。实际缺少电芯/接线/限值的功率测试，不用语言模型猜参数启动；先补齐该次测试所需事实。

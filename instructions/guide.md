# 从“能读数”到“可信数据集”：BMS 实施与验收指南

**你的主线是对的：先把测量做可信，再验证功率级，然后闭环控制，最后积累可用于 SOC 的数据。** 需要修正的是：ADBMS 不会替你算好外接电路的电流和温度；占空比到功率不是固定的一条标定曲线；数据记录要从第一阶段开始；SOC 的参考依据需要单独建立。

本指南依据当前源码、课件、实验步骤、官方器件资料及你提供的其他工程 instructions。这里提出的是下一步执行方案，尚未完成任何硬件验收。

## 1. ADBMS 已经做了什么，MCU 还要算什么

可以把 ADBMS1818 理解为带内部 ADC、参考源和数字接口的多节电池监测前端。它完成模拟输入到数字码的转换，主控通过 SPI/对应通信链读寄存器。**“已数字化”不等于“已变成安培和摄氏度”。** 外接分流电阻、放大器、温度传感器与接线属于你的板子，芯片并不知道它们的完整参数。[ADI 官方数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/adbms1818.pdf)

| 过程/公式 | 谁负责 | 是否仍需软件 |
|---|---|---|
| ADBMS 内部模拟采样、ADC 转换和硬件数字滤波 | ADBMS 硬件 | 不用自己重写 ADC；需要配置模式、启动、确认完成 |
| 读取寄存器、检查 PEC、组合字节 | MCU 芯片驱动 | 必须做；SPI 只是搬数据 |
| 本项目电芯/AUX 的 `V=raw×0.0001` | MCU 驱动的换算辅助函数或测量层 | 仍需做；不要再乘 STM32 的 ADC 比例 |
| `I=(Vsense−Vzero)/(s·G·Rshunt)` | MCU 板级测量 | 必须做，或使用独立标定得到的 `I=a·raw+b` |
| 分压电压→电阻→PT1000/NTC 温度 | MCU 板级测量 | 必须按实装传感器做 |
| `P=V×I`、能量积分、SOC | MCU 应用层或离线处理 | 芯片没有替整个系统完成这些算法 |
| `e=Iref−Imeas`、PI、PWM 更新 | MCU 实时控制 | 必须做，是执行控制的部分 |

用一个纯算术示例说明：AFE 读出 9750，换算得到 0.9750 V。若实际零点是 0.9000 V、完整通道灵敏度确为 0.75 V/A，则电流是 0.100 A。这是说明换算关系的示例，不是此板的实测标定。更换放大器增益，最后一步结果就会变化，芯片传回的电压码本身并不会替你选择新系数。

现有 `main.c` 已在 BMS_ReadReg 中做 `raw×0.0001`，BMS_ReadSample 再做电流与 PT1000 换算。因此不能把这些全删掉，只留 SPI 读取。较合理的重构是：器件驱动保留通用命令和码值解释；板级测量统一存放通道、传感器模型和标定版本；控制与 SOC 放在上层。详见 [测量分层](specs/measurement.md)。

## 2. 课件中的 STM32 ADC 主要在干什么

这个工程有两条采样链，而不是“STM32 ADC 再采一次 ADBMS 发来的数字量”。

```text
电芯端子、温度分压、电流调理信号
    → ADBMS 内部 ADC → 寄存器 → SPI → 慢速监测、记录、保护输入

电流分流/放大器的模拟输出
    → STM32 ADC1 → 本周期电流 → PI → TIM1 → 驱动器 → MOSFET/电感
                                  ↑                    ↓
                                  └──── 实际电流反馈 ──┘
```

课件安排 STM32 ADC1 提供较快的电流反馈。TIM1 让 PWM 与采样具有确定的时序，PI 根据电流误差改占空比。它首先完成的是**恒流控制 CC**。

“第二层使用 ADC 追踪功率”这个说法不够准确。ADC 读的是引脚电压；经过电流测量电路和换算才得到电流。计算电池功率还需要对应的电池组电压：`Pbat=Vpack×Ibat`。这里三个 V 是三节单体电压，组电压需按实际串联关系求和，不能拿某一节电压乘整组电流就叫整组功率。

恒流时电池电压会变化，所以功率也会变化。以后若要恒功率 CP，可设计受限外环 `Iref≈Pset/Vpack`，再交给内层恒流环；必须限制电压过低、给定电流与动态响应。课件现有目标不能自动扩展为已经完成恒功率或最大功率点追踪。

课程提出的 100 kHz 控制目标对应 10µs 一个周期；1 Hz 上位机显示是另一种任务频率。不要把打印、阻塞 SPI、OLED 更新或模型推理放进每个电流控制中断。完整采样与计算时延要实际测量，不能只根据定时器配置认定达到 100 kHz。

## 3. 你提出的步骤，哪些保留、哪些调整

| 你的理解 | 调整后的做法 | 原因 |
|---|---|---|
| 测量 V/I/T，用串口 CSV 与实际值标定 | 正确；同时保留原码、采样时间、质量标志和独立参考读数，先拟合再独立验证 | 只有转换后的曲线，无法区分 ADC、系数和清洗造成的误差 |
| 标定 PWM 与输出功率关系 | 先验 PWM 波形和驱动，再测不同工作点的 D→V/I/P 响应 | 电源、负载、电池 SOC、温度和模式会改变关系，不能得到万能 D-P 表 |
| 开环让测量数据改变 D | 固定 D 或预设 D 时间表，测量用于观察和保护 | 若根据输出误差自动修改 D，就已经是反馈闭环 |
| 之后加入 PI | 正确；先确认反馈符号、采样相位与停止路径，再加限幅、抗饱和、软启动和换向状态机 | 单个 PI 公式不等于完整电源控制系统 |
| 最后才加上位机 | 最小日志工具从测量阶段开始；完整界面与实验编排后置 | 标定和闭环调试本来就需要保存证据 |
| 上位机做 SOC 校正，再得训练集 | 先定义容量、初始 SOC、电流/时间基准和标签算法，再由上位机采集/组织数据 | 图形界面不能替代独立的参考 SOC |

电脑端把串口流存成 CSV 完全可行，但不要求 MCU 一定逐行打印 CSV。MCU 可以输出有版本的文本帧或二进制帧，PC 再转换；关键是能复原 raw、时间、状态、固件和标定身份。现有上位机与模板目前协议不一致，不能凭能打开 COM 口就认为联调完成。

在开环测试中还要区分 `Ibat` 和 `Iload`。Boost 输出侧通过 `Vout/Rload` 得到的是负载电流，不是电池侧电流。相同电路两端的电压、电流本来就不同，另有损耗，不能跨端相乘。

课件把 D 定义为上管占空比，因此放电 Boost 的理想关系写 `Vout≈Vin/D`；常见教材用低侧开关占空比，表达式可能是 `Vin/(1−Dlow)`。先统一 D 的物理定义，再比较曲线。它们都是特定工作条件下的近似，不是误差为零的验收模型。

## 4. 推荐路线与每一步的完成边界

以下是路线总览，详细前置、方法、判据、证据及失败回退见 [G00—G07 验收标准](specs/acceptance.md)。数据工具可以提前并行开发；带载实验必须满足它所依赖的测量、波形、边界和停止条件。

| 阶段 | 要回答的问题 | 完成时应拿出的证据 |
|---|---|---|
| G00 基线 | 这块板、这份源码、这份固件和资料能否对应？ | 硬件表、源码/固件哈希、构建日志、链接地址、待确认项 |
| G01 测量 | V/I/T 在规定范围内到底准不准？ | 两路电流各自标定、V/T 记录、独立验证误差、无效数据处理 |
| G02 波形与时序 | 实际 PWM 和采样是否符合设计？ | 示波器频率/占空比/有效死区、ADC 触发及完成时序 |
| G03 受限开环 | D 如何影响本工况的电压、电流与功率？ | 固定工况逐点记录、方向确认、理论偏差、停止证据 |
| G04 PI 恒流 | 能否稳、准、及时地跟踪并退出？ | 正负方向误差、瞬态、饱和恢复、时限与故障停止 |
| G05 接口联调 | 人机命令与实际执行是否一致？ | 协议、应答/应用值、分片粘包、断连和恢复、连续日志 |
| G06 SOC 数据 | 时间、测量、容量和标签是否可信且可复算？ | 参考链、容量/初值依据、数据质量报告、标签与划分版本 |
| G07 模型部署 | 离线、量化、板端结果是否一致且不干扰控制？ | 独立评估、黄金输入对比、内存/时延、快环并发回归 |

**最小功能完成**可以先定义为 G00—G05：可靠测量、双向恒流、本地/远程设置、可控停机和可追溯日志。**可用于建模的数据完成**是 G06；模型训练与端侧部署属于 G07。这样每一阶段都有自己的交付，不会把“上位机能画曲线”和“模型数据合格”混成一个终点。

## 5. 验收线如何定，才能既具体又不乱承诺

先把“指标数值、适用条件、测量方法、判定规则”四项写齐。`误差<5%` 若不说明哪个量、哪一段时间、相对什么参考、量程多少，仍然无法验收。

| 类型 | 本项目例子 | 使用方式 |
|---|---|---|
| C：课程明确要求 | PWM 100 kHz；±0.5 A 稳态误差<5%；D为0.40～0.90；测量上传1 Hz | 记录来源，补齐方法和容差定义 |
| E：工程建议草案 | 给 ±0.5 A 闭环分配 ≤5mA 测量误差预算；具体稳定窗口/纹波/响应指标 | 先检查仪器与板卡能力，再在正式验收前确定，不能称课程硬指标 |
| H：必须确认的硬件边界 | 电芯型号、电压/温度/电流限制、负载功率、驱动死区、停止延迟 | 保留 null，取得原理图/规格/实测后填写，不用讲义默认值代替 |

例：课程的 ±0.5 A、误差<5% 等价于稳态电流绝对误差<25mA。应使用独立参考电流，在预先选定的稳定窗口计算指标；纹波和峰值另列，不允许均值合格就掩盖瞬时越限。建议采用保守判断 `|误差|+U95<25mA`，其中 U95 是该比较的不确定度，不是随意加的余量。[不确定度基础：NIST TN1297](https://www.nist.gov/pml/nist-technical-note-1297/nist-tn-1297-6-expanded-uncertainty)

举例：误差20mA、U95=3mA，按上述规则可通过；误差24mA、U95=3mA则落在不确定区，不能硬判通过。两个数都是演示，未从这块板测得。

电流精度不能只定百分比，零点附近需绝对误差要求。SOC 又对长期偏置更敏感：1Ah 电池若持续偏置1mA，积分1小时会产生0.1个百分点的SOC偏差。这说明“满足恒流实验”未必已经足够“高精度SOC数据”。具体预算应由容量、实验时长与目标误差倒推。

## 6. SOC 的“校正”应该拆成什么

第一步是测量标定；第二步是规定条件下的容量测量；第三步是给初始 SOC 一个有依据的锚点；第四步才是电流和时间积分；随后才能比较 SOC 估计器或训练模型。

充电为正、容量单位为 Ah、时间为秒时，可写：`SOC[k]=SOC0+Σ(Ieffective·Δt)/(3600·Qref)`。SOC 用0～1比例，乘100才是百分数；效率定义、容量口径、积分方式和缺口处理必须一致。上位机可以执行这些计算，但可信度来自测量与参考方法。

用同一个有偏置的板载电流产生 SOC 标签，又用它证明自己的 SOC 算法精确，会形成同源自证。可以用这样的数据做原型，但应称“代理标签”。更强的参考方案用独立校准的电流与时间链，并报告初始SOC和容量的不确定度。独立参考也不是没有误差的绝对真值。

HPPC/DST 等动态工况会暴露另一问题：1 Hz 的瞬时电流点不一定保留这一秒流过的电荷。可以保存更高频电流，或输出有明确时间窗的平均电流/累计电荷，并验证聚合算法。显示1Hz、SOC输出10Hz、控制100kHz是三个不同频率，重复输出旧值不能增加数据带宽。

训练集应先按电池/完整循环/实验段分组，再切时间窗口。课件的8:2划分是课程要求；若要宣称泛化精度，建议另设未用于调参的最终测试集，例如80%开发数据内部做训练/验证，20%锁定测试。不能先切高度重叠窗口再随机8:2，也不能用测试集拟合归一化或选择量化参数。详见 [数据规范](specs/data.md)。

## 7. 旧 instructions 应怎样改

保留的是研究纪律：问题可判定、方法可重复、标准先确定、失败有记录、结果能独立复算。替换的是赛题、几何模型、官方比赛次数、原有模型额度策略和历史截止日期。详细文件映射见 [迁移说明](MIGRATION.md)。

不必让每个小修改都写五份文件。小任务使用一张工作卡，仍包含“问题、设计、判据、执行、结果”五部分；每次正式运行一份 manifest。状态只维护一处；RUNLOG 只追加会改变结论的动作。

```text
需求 R-I-CC：±0.5 A 稳态误差<25mA
  → 工作卡 U04 / 测试 T-CC-POS、T-CC-NEG
  → 判据版本、实际固件/配置/标定哈希
  → run_id
  → raw：参考电流、板载数据、PWM、状态与事件
  → derived：按固定脚本计算误差/纹波/响应
  → result：pass / fail / inconclusive / invalid
```

这是说明追溯结构的示例，还没有对应的实验 run。编译成功只能支持构建结论；示波器测得 PWM 只能支持波形结论；只有相应电流证据才能支持恒流通过。

MCP 可以在这套证据链上逐步实现“修改代码→构建→回放/测试→计算指标→定位问题”的开发闭环。建议先做离线构建和日志回放，再接下载器与仪器。实时 PI 留在 MCU；工具执行只允许在已定义的实验边界和当前授权内进行。更详细的未来接口原则见 [执行规则](WORKFLOW.md)。本次只是设计，没有创建或启用 MCP。

# G03 真实 ADC 禁能实现与验证（r4）

## 本次范围与结论

已移用独立HEX的标称电流换算，实现真实ADC采样、MCU本地原码窗口/ADC看门狗、失联与过期退出、禁能扫描及轨迹导出，并完成当前条件下的软件和板上验证。没有启动实际充放电。1008与2048差异的具体外部模拟链根因仍未闭合，不以静态零点重置冒充电流标定。

接线沿用用户确认：三节真实电池、33Ω负载、充电接口开路。固件g03-adc-r4；Release SHA256：`b9ffb2024a164cc299b6edbeb1644bd1f64b5815854195ffed84aaa0502dda26`。正常BOOT下经SWD写入、读回验证和软件复位后运行；本轮没有新增冷启动测试。首遍写入的校验不一致原始日志保留，第二遍验证成功后才运行。Release 0错0警告；Debug 0错、1条已有EXTRAM链接警告。源码清单与实际文件哈希已核对。

## 1008/2048排查得到什么

| 对照 | 实板结果 | 支持的结论 |
|---|---|---|
| 关闭/开启2次平均 | 历史Start/Stop模式稳定段约1262/1274码 | 不支持多右移一位造成二倍差 |
| ADC内部自校准 | CALFACT由0变4附近，稳定段约少4码 | 内部偏移校准不能补足约1000码差值 |
| 11.5→1499.5采样周期，r2外设对照 | 起始偏低仍存在，稳定值仍约1230而非2048 | 长采样时间未解决；恢复默认采样时间后重新测试 |
| 持续ADEN，2ms节拍，r3 | OSoff约1619、OS2约1493 | 外部读数对采样工作方式敏感 |
| 持续ADEN，1ms节拍，r4 | OSoff约1469、OS2约1396 | 基线和监控必须固定同一工作方式；不能套用旧1008零点 |
| 片内VREFINT，1499.5周期，1ms节拍 | OSoff均值1818.6875、OS2均值1818.4375 | 按片内0.8V标称值推算VREF约1.8013/1.8015V；未见ADC整体二倍比例错误 |
| 恢复500ms G01启停模式 | MCU 1007—1013码，AFE 8994—9004码 | 模式变化再次复现；AFE标称约0.9V不等于已证实MCU引脚也为0.9V |

片内对照仅临时更改通道选择、预选、采样时间和VREFINT内部通路；未启用VREFBUF输出、未写OTP。全部寄存器保存、恢复并读回核验，随后外部通道SQR1=64、PCSEL=2。原始数据及覆盖期间通道身份见`internal-reference-probe/manifest.json`，覆盖期间的外部电流标签不能用于电流分析。

片内0.8V标称值见[ST器件数据手册](https://www.st.com/resource/en/datasheet/stm32n647i0.pdf)；1.8V ADC供电与外部参考边界见[ST AN5967](https://www.st.com/resource/en/application_note/an5967-getting-started-with-hardware-development-for-stm32n6-mcus-stmicroelectronics.pdf)。这是标称一致性对照，不是外部仪表标定。核对[ES0620](https://www.st.com/content/st_com/en/technical-documents/es0620-stm32n6xxxx-device-errata-stmicroelectronics.html)时未据双ADC/注入转换条目推断当前单ADC常规转换根因，也未盲改参考驱动。现有证据优先指向外部输入路径/建立行为，但不足以确定断线、阻抗、偏置或器件具体原因。

## 实现与修订

HEX模型ID为hex-dd44fae1-nominal-v1，K=1.3266666730244954 A/V、MCU LSB=float32(1.8/4095)、AFE LSB=float32(0.0001)。G01使用0.9V标称零点的estimate，physical_valid恒0；相对诊断扫描使用固定工作方式下的假定静态基线，不修改原码。

r1首条状态响应触发栈溢出，r2将1024字节响应缓冲改为主循环常驻，并加入512字节栈帧编译检查。r2起始偏移触发稳定性拒绝；r3保存64点、单列前16点启动观测，以后48点检查稳定性，但HAL_Delay(1)实际等待两个tick，切入1ms监控后原码1407越出1408下限，第2个样本即AWD+软件窗口故障96锁存。r4按本地HAL实现改为下一tick采样，保持ADEN，基线与启动预采样、监控采用相同1ms节拍。32码稳定性判据和50mA标称诊断窗口均未放宽；启动前漂移超窗时拒绝，不重新居中。全部失败保留在r1/r2/r3目录。

启动预采样属于禁能诊断，不能挪作带功率运行时的保护空窗。G01仍是原有500ms启停采集；其ADC_profile字段记录最近选择的配置，不表示G01也持续开启ADC。

## 实际验证

- 原生生产C核心、适配层、UART、Python解析和G01—G03回归通过；包括过期、原码越限、清理失败、不稳定/漂移拒绝、非法量程、请求重放及10000事件合成序列。模拟中的1008→2048输入变化仅是夹具，不是实板结论。
- 真实ADC板测六组通过。1秒扫描恰好1000次完成，107条轨迹；2秒上界扫描2000次完成，207条轨迹，均无环形覆盖，五个影子CCR完整。扫描不写实际TIM CCR。
- 上/下两侧移窗分别由真实ADC触发AWD并锁存，均第1个完成样本触发；这些是人为改变诊断阈值的测试，不是真实电池过流。关闭主机句柄和重复心跳均触发MCU本地800ms失联退出；STOP/CLEAR通过，清故障不自动启动。
- G02回归通过：10秒TIM更新/ADC完成均999998，OVR、ADC错误、迟到中断均0；引脚门为0。两方向合成状态机与十种故障等8组通过，共141份状态响应，actual_bits=0。
- G01恢复采集30秒：531条有效原码、59个完整九通道组，内部缺序/重复0。停止采集时截断1个末尾行，原始文件与partial_tail事件保留，未计作有效数据；不能写成零记录错误。
- 真实ADC主套件339份响应中39份状态、最大窗口套件及最终状态均显示actual_bits/power_capable/physical_valid=0。最终state=0、faults=0、configured=0、owns_adc=0，恢复常规采集。

中断内周期计数仅表明软件路径到禁能寄存器写入的观测，不能当作MOSFET/继电器实际电气停止延迟。硬件独立看门狗、外部电流标定、引脚波形与功率级响应没有在本轮验证。

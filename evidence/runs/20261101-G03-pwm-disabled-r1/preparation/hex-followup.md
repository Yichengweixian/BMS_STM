# HEX 后续资料对本次禁能接入的影响

日期：2026-11-01。范围：只读资料/源码核对；本次未运行老师HEX、未访问串口/SWD、未更改实际工程。对应输入为 `20261101-HEX-baseline-followup/baseline-plan.md` 和其 r2 candidate。

## 应当沿用的新结论

1. **死区来源允许来自EG3112。** 课件slide8与实验步骤paragraph102明确说本板EG3112提供内部死区、TIM1可不另设死区；厂家V1.1手册也给出内部死区和互锁。r1要求任何情况下DTG>0过严，r2的 `deadtime_source` 更合适：DRIVER可接受DTG=0，TIMER/BOTH要求DTG>0，未指定来源仍拒绝。该条件应进入固件profile和日志，不能由注释代替。
2. **本次禁能版本不需要因缺完整原理图停工。** 定时器可以产生内部TRGO和ADC采样，PA9/PF7保持GPIO低、CC2E/CC2NE与MOE关闭、PB5/PG5低。此时CEN运行是内部时基，不等同于引脚输出已开启。应分别报告内部计时状态与实际输出位。
3. **老师HEX可作为受控对照对象，但不是本轮必要下载。** 原版STOP下的身份、零点接受/拒绝和静态原码能够帮助区分软件采集模式差异。它不能在无电流变化时确认斜率/方向、不能证明PWM支路和继电器支路测同一电流，更不能从一个上位机电流字段推断该字段来自PA1。当前独立禁能port仍可先完成。

r2当前源码哈希与其validation.json一致，16组主机测试通过日志存在，本次没有重跑。上一run的Cortex-M55命令使用 `-fsyntax-only` 且针对旧candidate，不能作为r2已完成目标链接或已生成可烧录镜像的证据；本次接入后需要实际新target构建。

厂家证据为[EG3112官方资料](https://www.egmicro.com/products/detail/?name=EG3112)及该页链接的[V1.1手册](https://www.egmicro.com/static/upload/drive/%E7%BD%91%E7%AB%99%E5%85%AC%E5%BC%80%E8%8A%AF%E7%89%87%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8C/%E5%8D%95%E7%9B%B8%E5%8D%8A%E6%A1%A5%E9%A9%B1%E5%8A%A8/EG3112%E9%AB%98%E5%8E%8B600V2A%E5%8D%8A%E6%A1%A5%E9%A9%B1%E5%8A%A8%E8%8A%AF%E7%89%87%E6%95%B0%E6%8D%AE%E6%89%8B%E5%86%8CV1.1.pdf)：第4页列出内部死区/互锁，第5页给HIN/LIN高有效和低电平关闭；第8页DT为50/100/300ns（最小/典型/最大，CL=0）；第10—11页真值表说明两输入同时低或同时高时，两输出关闭。100ns不是本板MOS的实测有效死区。网页/手册支持器件功能，不自动确认实装器件及板上信号对应。

## 原版STOP对照的边界

可证明的范围是指定HEX/板型在STOP入口的启动、参数、零点处理和静态测量，以及显式功率STOP命令的路由。`stream stop`只停止数据流，业务停止是`bms mode stop`。未发生输出时收到STOP响应不证明带载电气关断时延。原版运行D由ADC回调改变，CLI data没有D，不能从初始化CCR500或一条电流数据恢复整个D(t)。若之后专门对照，应独立run、先确认镜像可恢复和STOP入口，不与本次禁能port验收合并。

本次未发现需要把完整原理图、非零DTG或G01全部精度验收作为禁能开发前提的理由。真实PWM放行仍需要本次路径/驱动身份及有限工况的依据；板上内部触发计时通过不能替代这一部分。

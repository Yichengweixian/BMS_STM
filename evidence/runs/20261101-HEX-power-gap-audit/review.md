**找到的软件依据足以缩小排查范围，并实现单次执行的候选控制逻辑；三项实物缺口不能仅凭老师 HEX 全部闭合。** 老师镜像同样依赖 PA1、电流 ADC 中断、零定时器死区，而且使用持续业务状态机。它不是当前板子的独立过流和单次截止验收证据。

## 逐项答案

| 当前问题 | HEX 实际恢复结果 | 解决办法与仍需的证据 |
|---|---|---|
| MCU 电流无明显响应 | 实时电流仍是 **PA1 / ADC1 CH1**；工作时TIM1_TRGO同步触发、6.5周期、OS2右移1。启动默认CH11会在进入控制时改成CH1+CH0 | 不改成CH11，不通过改系数制造响应。保留原码，优先核对I_AD与I_ADA连线及继电器/PWM支路。软件候选采用持续使能、确定触发相位、AWD先行和样本新鲜度检查；必须确认该输入实际随相关支路电流变化 |
| 快速过流或独立保护 | AWD1监测CH1，**8次连续越界过滤**，由CPU中断执行HAL关断；Break/Break2关闭 | 可实现快速ADC保护，但不能称为CPU无关保护。新适配器应先撤销MOE/AOE，再记录和清理，拒绝不可观测阈值；独立保护需要已确认的比较器/驱动故障源到BKIN或驱动EN的电气连接 |
| 高低侧与死区 | PA9=TIM1_CH2、PF7=CH2N；主/互补高有效。老师也设**DTG=0**，还开启AOE、设置互补idle高 | 已恢复MCU端配对，未恢复PCB高低侧走线。先确认驱动型号、输入极性、是否内置死区与关闭电平；按数据手册/实测确定非交叠时间。不能把软件DTG=0直接解释为实物有效死区为0，也不能由它推导一个可用非零数值 |

## 1. 电流问题排查已经可以收窄

老师默认ADC1配置的CH11见 `0x70101622..0x7010163a`；真正工作配置在 `0x70105bb8`：rank1=CH1、rank2=CH0，AWD只监测CH1。MSP初始化同时明确将PA1设为模拟输入。它没有给出“另一条已证实可用的MCU电流引脚”。

当前短/长采样约1232–1272码，按老师标称 `1.8/4095` 换算约0.542–0.559V。老师的五次校零只接受约0.75–1.05V，否则保留默认值；直接复制校零不会解决当前输入无响应。内部ADC自校准、零点估计和整条电流路径的斜率/方向验证是三个不同问题。

下一步应把排查对象锁定在以下位置，而不是继续修改电流公式：

1. **I_ADA到I_AD/PA1的连接或缓冲/分压。** 板厂应提供这两条网络、放大器输出、核心板连接器与PA1的连线；断电通断和受控电压响应也可建立该证据。
2. **电流经过哪个支路。** 三次继电器动作能使AFE变化，不能证明PWM功率回路与该动作必经同一条MCU测流支路；目前既不能判定PA1断线，也不能判定它在PWM工况可用。
3. **模拟建立时间。** 已有PA1短/长采样随设置变化的事实，说明缩短到老师的6.5周期不是自动修复。输入驱动能力/阻抗未清楚前，不将较短采样当作推荐值。

软件侧可复用TIM1同步触发思路。首个单点版本宜让ADC1专门采CH1，并以ADC2/DMA承担其他量；若采用老师的CH1+CH0序列，必须正确使用STM32N6的ADC FIFO、记录样本身份并处理溢出。N6在保留模式有FIFO，不能套用其他STM32系列“连续读DR一定得到同一个数”的结论，见 [手册交叉核对](verification-notes.md)。

## 2. 过流关断不能整套照搬

已恢复完整链：

```text
ADC1_2向量 0x701025f0
  → HAL ADC IRQ 0x701083f8
  → AWD回调 0x7010119c
  → fault记录 0x701060c8
  → 停止函数 0x70106cf8
  → PB5/PG5低 → 主PWM停止 → 互补PWM停止 → ADC停止
```

老师AWD有8次连续越界过滤；HAL先处理完成回调，再处理AWD；切换标志有效时AWD回调还会提前返回。即使外设判窗是硬件完成，撤销输出仍依赖转换、NVIC、CPU及软件。HEX没有提供一个已经接通的独立BKIN故障源。

候选软件采用以下改变：IRQ入口优先检查AWD/OVR；先调用当前 `G02_EmergencyOff` 撤销MOE/AOE和输出使能，后记录故障和清理ADC；启动前就确认ADC窗口可观测，原码近轨、未知斜率或无法覆盖的限值不允许放行。过滤次数必须由噪声和允许响应时间选择；本轮不把8次或1次指定为实物合格值。AWD、OVR、采样过期、停止命令和执行期限进入统一锁存出口。

独立方案的必要链路是“有实际电流输入的比较器/驱动故障输出 → 已验证的BKIN或驱动EN → 硬件撤销PWM”。仅把 `BreakState` 宏改成ENABLE，不能创造缺失的故障输入。外部电源限流是供能约束，也不能代替半桥交越电流的快速保护。

## 3. 驱动时序和死区的明确结论

| 字段 | 老师 HEX | 当前源码 |
|---|---|---|
| PA9/PF7复用 | TIM1_CH2 / CH2N，AF1 | 相同 |
| PSC / 模式 / RCR | 0 / 中心对齐1 / 1 | 相同 |
| ARR | 1999 | 2000 |
| 初始CCR | 500，之后覆盖 | 1000，诊断初值 |
| DTG | 0 | 0 |
| Break/Break2 | 关闭 | 关闭 |
| AOE | 开启 | 关闭 |
| 互补idle | SET | RESET |

配置位于 `0x7010171a..0x701017d4`，引脚位于 `0x70102410`。若TIM1时钟为400MHz，中心对齐下老师ARR1999约100050Hz，当前ARR2000为100000Hz；这是条件计算，不能替代老师镜像时钟或实测频率。RCR=1控制更新节拍，不把载波频率再除2。

老师业务中有停机后100ms等待、继电器命令有效后20ms等待，再启动ADC和PWM的路径。这些只是代码参数，不是本板继电器触点释放/吸合的实测期限。故障关断宜复用当前“先撤销PWM再做其他处理”的结构，并在确认驱动输入极性后核对GPIO低电平的实际作用。保持AOE关闭，防止只清MOE后被自动更新再次放行。

**高/低侧对应关系、实际Vgs关断及有效非交叠时间仍需驱动/走线资料或波形证据。** 老师HEX不包含这些事实。本轮不指定一个凭空的DTG或把原课件的占空比方向推广到未知接法。

## 4. 单次PWM候选控制核与接入位置

[candidate](candidate/README.md) 是本轮新写的实现，不是老师源代码。它与当前Keil工程隔离，实际PWM端口没有接通。控制核提供：固定CCR和参数快照、缺少条件拒绝启动、消费一次令牌、本地周期IRQ截止、样本过期和心跳期限、异常锁存、关闭回调优先于延迟清理。16组主机测试全部通过，另以Cortex-M55目标编译检查通过；独立复查发现的断采超时被新样本掩盖问题已经修复并有回归测试。测试中的参数都是合成夹具值。

接入现有工程的明确位置：

1. 从 `BSP/g02_port.c` 复用寄存器关闭和成对输出放行；确认GPIO关闭电平后由新的 `g03_pwm_port` 统一拥有TIM1、ADC和继电器。
2. 从 `BSP/g03_relay_port.c` 复用TIM2本地IRQ与DWT截止的结构，把PWM期限检查放在独立周期IRQ，不能依赖串口或主循环继续运行。IRQ方案仍依赖CPU，不能替代独立硬件保护。
3. 在ADC IRQ最前端接AWD/OVR；将HardFault等、STOP、协议异常、输入过期接入同一关闭/锁存路径。运行中拒绝修改CCR，不允许心跳延长总执行期限。
4. 保留现有禁能诊断的编译隔离。增加独立候选target和板级port，不能直接翻开 `G02_ALLOW_PIN_OUTPUT` 并删除已有 `#error`。
5. 编译和离线故障注入通过后，仍需核对真实IRQ时延、输出关闭效果和启动工况，才形成可执行的功率版本。

当前板上仍按历史记录是继电器版。本轮候选core通过测试不等于已经有完整可烧录的真实PWM固件。候选API采用毫秒时间戳；期限判定存在周期IRQ间隔、执行延迟及量化误差，不能将run_ms直接当作最大电气通电时间。若本次能量/停止约束要求微秒级界限，必须改成对应时间基或经验证的硬件截止，不能把硬限向上取整放宽。

## 5. 本次占空比、期限与供能约束如何确定

HEX里的CCR500约25%仅为初始化值；课件0.90和继电器试验约99ms也不能直接变成本次PWM工况。前三者的物理含义和保护前提不同。本轮在 [pending-profile.json](pending-profile.json) 中明确保留待定值，不让程序自选默认值。

需要冻结的一组参数为：实物高侧定义下的D及对应CCR、经确认的非交叠时间及DTG、单次最长有效输出时间、可观测电流窗口与最大样本间隔、供能源/限流/输出电容、其他供能路径状态、停止后的电流续流路径。若使用限流台式电源替代电池，还需确认通道隔离、反灌/吸收能力和接线；三个真实电芯本身不会服从台式电源的限流设置。

33Ω/25W负载标签只能约束已知负载路径的电压/功率估算，不能限制开关交越、电感峰值或输出电容的短时放电。脉冲时间的上界必须与可接受峰值、总能量及停止能力一起确定；当前没有足够事实给出一个可执行的数值。

因此本轮已经交付“如何实现和验证”的代码与证据，仍未完成的是实物输入路径、驱动/关断事实、工况参数及板级接入。这些项目在 [result.json](result.json) 分别记录，没有将静态结论升级为硬件通过。

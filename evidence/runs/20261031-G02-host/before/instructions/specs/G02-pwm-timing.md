# G02 PWM、ADC 同步与停止：软件契约和测量方法

适用范围：G02.1—G02.3 的实现与离线验证，以及 G02.4—G02.5 的待执行测量。阶段状态只在 [STATUS](../STATUS.md) 维护；本次实际执行命令、源码和产物哈希、日志与结果写入对应工作卡。本文中的配置推导不是实测波形，也不表示允许带载。

判据来自 [G02 验收条款](acceptance.md#g02无功率-pwm采样时序与强制停止)，具体实物参数、禁能条件和限值只在 [hardware-profile](hardware-profile.json) 维护。最新既有记录为负载已接入、真实电池已移除并接了三路模拟源；这些历史信息不能代替测试当天的输出状态及隔离确认。

## 1. 时钟和 PWM 定义

真实构建入口是 `BMS_EXv1.1/BMS_EX/Appli/Core/Src/main.c`，工程是 `MDK-ARM/Appli/BMS_EX_Appli.uvprojx` 的 `BMS_EX_Debug` 和 `BMS_EX_Release`。Debug 自行配置系统时钟；Release 从既有 FSBL 继承时钟，FSBL 源码身份未建立。

STM32N6 的 TIM 内核使用 TIMG 时钟。项目自带 HAL 的 `HAL_RCCEx_GetTIMGFreq()` 调用：

```text
f_TIM = f_SYSCLK / 2^TIMPRE
```

其中 TIMPRE 编码 0/1/2/3 对应除以 1/2/4/8。不能套用其他 STM32 系列的 APB 分频后乘 2 规则，也不能把 CPU 时钟当 TIM 时钟。`hal_rcc_ex.c` 的该函数和 `stm32n6xx_ll_rcc.h` 的 `LL_RCC_CALC_TIMG_FREQ` 是本项目所用实现依据。

Debug 配置的名义推导为：HSI 64 MHz，PLL1=`64/2×25=800 MHz`，IC2 再除以 2 得 SYSCLK 400 MHz；TIMPRE 除以 1 时 TIMG 为 400 MHz。AHB 除以 2、APB1/2 除以 1不改变这一 TIMG 公式。原 `PeriphCommonClock_Config()` 曾只有定义而没有调用，本版已在两个target共用的初始化路径中显式调用，选择TIMPRE除以1及CLKP=HSI。诊断启动读取 `HAL_RCCEx_GetTIMGFreq()`、`HAL_RCCEx_GetPeriphCLKFreq(RCC_PERIPHCLK_ADC)` 和CPU时钟；TIM必须读回400 MHz、ADC必须读回64 MHz且CPU时钟非零，否则锁存时钟故障、拒绝启动。上述是软件守卫，尚不能仅凭Debug公式宣称Release实板已读回这些值。

| 项目 | G02 诊断配置/解释 |
|---|---|
| TIM1 计数时钟 | 内部时钟，PSC=0；实际频率由运行时 TIMG 读回 |
| 计数方式 | `CENTERALIGNED1`，ARR=2000，CKD=1 |
| 完整 PWM 周期 | `2×ARR×(PSC+1)/f_TIM`；中心对齐不套用边沿对齐的 ARR+1 公式 |
| 名义频率 | TIMG=400 MHz 时为 100 kHz，周期 10 µs |
| 比较值 | 50%逻辑占空比使用 CCR2=1000；旧模板 CCR2=500 对应25% |
| 输出 | PA9=TIM1_CH2，PF7=TIM1_CH2N；PWM1，CH2/CH2N均高有效 |
| D 的定义 | 本阶段 `D_logic=CCR2/ARR` 表示 PA9 的逻辑高电平占比；PF7名义为其互补 |
| 上管 D | MCU 引脚到驱动输入、再到上管的实际映射及有效电平须由接线/波形确认；不直接令 `D_logic=D_upper` |
| 预装载 | ARR预装载开启；本项目HAL的 `HAL_TIM_PWM_ConfigChannel()` 自动开启 OC2PE |
| 更新与触发 | RCR=1；TIM1 TRGO=UPDATE，TRGO2=RESET |
| 死区和故障输入 | 原TIM死区为0；BKIN/BKIN2关闭；AOE关闭。内部驱动死区及实际故障输入仍须单独确认 |

中心对齐每个完整周期经过一次上溢和一次下溢。RCR=1时，稳态UEV/TRGO每两次边界事件产生一次，即名义每完整周期一次。上下端的实际触发位置取决于启动时的CNT、方向和重复计数器初始化；记录设计位置，并以波形验证。

停止状态下执行UG使预装载及重复计数器进入已知状态。本版准备期间暂用TRGO=ENABLE且CEN=0，避免TRGO=RESET把UG传播成触发；UG后清UIF，再恢复TRGO=UPDATE，然后arm ADC。HAL启动ADC时清除转换旧标志；TIM1待处理中断在使能前清除。运行中不得为了立即改变D而随意发UG：这会改变采样事件及相位。CCR正常更新通过预装载，在后续UEV才进入有效比较器。中心对齐时DIR只读；本版重启先停计数并暂时清CMS，再清DIR、恢复CENTERALIGNED1，然后设CNT=0并发UG，避免沿用上次下降计数方向。首次与重复启动的实际相位均纳入波形用例。

## 2. ADC1 诊断和 G01 的所有权

G01 的常态路径是ADC1软件触发、每500 ms轮询一次。G02诊断期间由诊断模块独占ADC1，G01任务暂停，不再执行 `HAL_ADC_Start/PollForConversion/GetValue/Stop`；退出诊断并完成清理后才能恢复G01。串口记录必须区分两种模式，不能将诊断完成计数当成G01的500 ms样本序号。

ADC1诊断配置为PA1/INP1、12 bit、单rank、非连续转换、TIM1 TRGO上升沿触发、DR读回、OVR preserved、2倍过采样右移1、11.5 ADC周期采样。先清旧状态并arm ADC，再启动内部TIM计数；ADC2保持停用。ADC2现有3rank、DR、EOC_SEQ的配置不能直接靠每序列读取一次DR来获取三路完整数据，后续需要专门的逐rank或DMA方案。

本项目 `stm32n6xx_hal_adc.c` 说明12位SAR核心转换为12.5 ADC周期。若运行时ADC内核读回64 MHz，则ADC1一次双采样的核心预算为：

```text
T_core = 2 × (11.5 + 12.5) / 64 MHz = 0.75 µs
```

此条件计算不包含触发跨时钟域同步、模拟建立、IRQ排队、ISR及CCR提交，也不是板上已测转换时间。ADC时钟改变时必须重算；物理采样准确性仍归G01，不因同步诊断计数正确而自动通过。

## 3. 可观测事件与不能直接推出的结论

设计事件链为：`计数边界 → RCR产生UEV/TRGO → ADC触发/转换 → EOS/IRQ → 读取DR → ISR返回`。CCR写入进入预装载，后续UEV再装载；UEV同时触发ADC时，该次转换对应的是更新边界之后的波形周期。

| 记录项 | 能说明什么 | 观察边界 |
|---|---|---|
| TIM1更新ISR计数 | 软件服务过多少次UEV中断 | UIF是标志位，多个事件可能合并；不等于独立硬件触发计数 |
| ADC EOS/回调计数 | 已处理的转换完成次数 | 必须结合OVR、错误及窗口首尾状态；不能单独证明无漏周期 |
| ADC OVR/错误计数 | 观察到的数据覆盖/转换异常 | 不能将异常样本当有效零值；保留故障原因并停机 |
| DWT入口/出口及最大周期数 | 已测软件区间耗时、ISR负担 | 入口前的IRQ延迟不在区间中；包含被抢占时间时须注明 |
| 相邻IRQ间隔 | 服务周期的稳定性及长间隔线索 | 不是ADC精确采样相位；32 bit回绕按无符号差处理 |
| ISR时的TIM CNT/方向 | 软件观察时刻在计数周期中的位置 | ISR读取有延迟，不能标成硬件触发的精确CNT |
| CCR提交值、提交计数及后续UEV | 软件请求和见到更新边界的关联 | 本版保守等待两次已服务UEV；第一条可能在写入前已pending。该记录仍不是有效CCR读回或实际引脚变更 |
| `stop_request_cycles/stop_cycles` | 包围 `G02_EmergencyOff()` 的软件执行区间 | 起点不含mailbox到主循环的等待；终点不是驱动或栅源关断时刻 |

快速路径只做有界寄存器访问、整数计数和时标，不在ISR打印、等待串口或访问AFE。本版诊断模块也不在主循环打印；停止并完成清理后，通过调试器导出 `g02_control` 和 `g02_telemetry`，保存原始内存/字段转录及对应镜像身份。TIM1更新与ADC1 IRQ使用相同抢占优先级以串行更新统计；ADC IRQ可能先于UEV IRQ被服务，不能按二者第N条记录强行配对。

`g02_telemetry.trace` 是128项事件环形缓冲，每项含DWT周期、TIM CNT/方向、事件类型与已服务UEV计数。`trace_written` 是总写入数，`trace_overwritten` 记录覆盖数，存储位置为 `seq % 128`；仅保留最后128项，不是整个窗口的完整原始轨迹。导出时按逻辑序号 `max(0, trace_written-128)` 到 `trace_written-1` 重排。事件1/2/3/4分别表示UPDATE、ADC完成、CCR写入、OFF；全窗口统计独立累积，环形覆盖不清空计数。下次获准启动会清空本次telemetry，因此必须先归档。

`ccr_next_uev_observed` 保存最新CCR请求在两次已服务UEV后观察到的值，`ccr_write_cycles/ccr_observed_cycles` 给出软件观察区间；它不是实际引脚占空比或shadow寄存器读回。若前次观察完成前再次写CCR，以最新请求为准，前次请求不具有独立生效证明。`late_update_irqs` 仅记录服务间隔大于名义周期1.5倍的次数，是诊断线索，不是冻结的合格阈值。

DWT启用及前进检查发生在启动准备时。`cycle_read_pair_cycles` 包含两次读数及DSB/ISB屏障开销，不是整个ISR的开销扣除值；各ISR最大周期字段也只包围代码中的测量区间。32 bit DWT在800 MHz下约5.37 s回绕，10 s窗口不能只用首尾DWT差推算时长；窗口使用HAL毫秒tick，DWT仅用于可确认小于一次回绕的局部区间。GPIO标记只在已经确认可用的引脚上增加，本版未分配标记引脚，不能把内存trace当作外部ADC采样相位波形。

用于正式10 s窗口的计数关系应在运行前冻结：排除UG及启动清理，记录开始/结束计数、实际窗口、停止时是否有在途转换。稳定完整周期理论数为 `f_PWM×T_window`；名义100 kHz、10 s是1,000,000次。首尾相位、在途样本的处理要明确，不能把少1次固定解释成允许误差。通过软件计数并不足以证明TRGO没有丢失，采样相位和CCR生效仍须外部波形交叉验证。

STOP优先撤销输出而不等待统计补齐：当时已经置位但未服务的UIF可能不计入 `update_irqs`，在途ADC可能被停止、或在清理前完成并再记一次。因此两类最终软件计数不能机械要求一一相等，也不能据差值直接计算漏触发数。应结合停止点相位、原始状态及外部波形解释窗口边缘；未消除歧义时保留缺测结论。

## 4. 默认态、启动门控和停止契约

常态启动只进入测量/停机状态，不自动启动TIM1 PWM、外触发采样或继电器。PA9/PF7配置为GPIO推挽LOW；TIM初始化后仍保持GPIO LOW，`HAL_TIM_MspPostInit()`只在获准的PINS启动中切换复用功能。继电器GPIO低电平是软件命令，实际触点是否开路及有效极性仍以profile中的实物证据为准。

诊断启动分为内部采样时序与引脚输出两个许可层。`G02_MODE_SAMPLING`只开内部计数和ADC同步，MOE=0、CCER=0，PA9/PF7仍为GPIO LOW。两个交付target的 `G02_ALLOW_PIN_OUTPUT` 均为0，`G02_MODE_PINS`请求返回 `G02_DISALLOWED`，不会开始准备或输出。引脚测试必须另建经审查的无功率测试镜像，并具备明确测试授权及禁能接线。软件许可参数、编译开关或测试代码中的布尔值均不证明物理隔离已经成立。源码存在启动入口不构成烧录或上电授权。

启动检查至少覆盖：未锁存故障、没有其他ADC1所有者、实际时钟及TIM/ADC配置相符、比较值有效、继电器保持禁能、前次清理结束。全部成立后按确定顺序预装载、UG、清标志、arm ADC、开启计数；引脚输出使能需保证CH2/CH2N共同受MOE控制，避免先后启动HAL两路产生单路窗口。启动首脉冲仍需波形检查。

STOP和故障路径先撤销MOE/输出，再停止触发源和执行清理；故障锁存后不自动恢复。中断内快速关断不能依赖可能等待HAL tick的阻塞停止，ADC HAL清理与恢复G01放在允许完成该工作的上下文。清锁存仅使系统回到可检查的停机态，不自动使能输出。初始化错误、CPU fault及复位后均须回到既定禁能状态；软件无法证明复位期间引脚、驱动器或继电器的真实电气行为。

本版 `G02_EmergencyOff()`先清MOE/AOE，再关TIM中断、CEN和CCER，将PA9/PF7恢复GPIO LOW并拉低继电器命令；不依赖HAL等待。`G02_Service()`在主循环停止ADC中断采样、恢复保存的G01初始化。清理失败会锁存ADC故障并保留所有权，禁止G01抢占ADC。Error_Handler、NMI及CPU fault处理入口调用快速禁能；对这些异常的实物响应仍需验证。

### 调试器mailbox及操作顺序

诊断入口是RAM mailbox，不是UART业务协议；串口不接受G02启动/停止命令。应用主循环调用 `G02_Task()`消费命令，随后仅在 `G02_MeasurementAllowed()` 为真时运行G01。

| `g02_command` | 枚举 | 行为 |
|---|---|---|
| 0 | `G02_CMD_NONE` | 无请求；每次消费后自动清零 |
| 1 | `G02_CMD_SAMPLE` | 使用 `g02_compare/g02_window_ms` 启动内部同步采样 |
| 2 | `G02_CMD_PINS` | 请求引脚输出；交付target门控关闭，返回DISALLOWED |
| 3 | `G02_CMD_STOP` | 强制停止；重复调用幂等，不清故障锁存 |
| 4 | `G02_CMD_FAULT` | 注入 `G02_FAULT_INJECTED`，关断并锁存 |
| 5 | `G02_CMD_CLEAR` | 清理完成后清锁存并回STOPPED；不启动输出 |
| 6 | `G02_CMD_COMPARE` | 运行中提交新CCR预装载值，不发UG |

`g02_compare`默认1000，允许整数1—1999；这是避免端点的诊断参数范围，不是已确认的带载D范围。`g02_window_ms`默认10000，允许1—10000 ms；该上限是诊断自动收尾措施，不是硬件允许运行时间或10 s截止期保证。主循环按HAL tick到期执行STOP，存在任务调度延迟；主循环失去服务时不能将其当独立硬件看门狗。

1. 在已有烧录和无功率测试授权后，确认待测镜像身份及PA9/PF7禁能状态。在尚未启动诊断时暂停CPU，设置 `g02_compare` 和 `g02_window_ms`，最后写入 `g02_command`，再自由运行。
2. 窗口内不设断点、不单步、不暂停CPU。内部采样结束后再读 `g02_command_result`、`g02_control.state/faults/cleanup_pending` 和telemetry；启动返回OK仅表示启动事务成功，最终状态及错误计数须另查。
3. 需要窗口内COMPARE、STOP或FAULT时，只能用已经确认不会halt CPU的RAM写入方式，仍先写参数、最后写命令。本版没有设置调试暂停冻结TIM，halt CPU时计数器默认仍运行而ISR/主循环不能处理；这种写命令方式只用于逻辑演练，不能判定连续时序或STOP延迟。有引脚输出时不得依靠暂停调试器来停止输出。
4. 停止并清理完成后归档快照。故障必须先完成清理、显式CLEAR，再另发START；复位清空mailbox，既有请求不会自动重放。

`g02_command_result`按 `g02_control.h` 的 `G02Result` 解释：0=OK、1=BAD_ARGUMENT、2=NOT_READY、3=BUSY、4=DISALLOWED、5=FAULTED、6=CANCELED。运行终态以state/faults为准，不能只看最近命令返回值。

现有窗口到期会在CPU自由运行时调用STOP，可用于无halt收集自动停止波形；后续测试镜像也可加入明确时刻的代码故障/停止注入并记录版本。真正人工STOP的触发引脚或业务接口、硬件请求到输出关闭的测量方法仍待制定；不能用一次暂停CPU后写mailbox的演练代替该验收项。

## 5. 示波器测量清单

开始前将本次实物边界补充到唯一profile并保存快照：当前源输出/电池/负载状态、能量隔离方式、驱动供电、继电器极性、可用STOP路径、接线照片、测点和探头。UNI-T MSO3034HD型号已登记，探头型号/衰减、参考方式、差分能力和实际采集设置仍未知。

1. **MCU逻辑层**：核实PA9和PF7的实际可用测试点、板上GND及逻辑电平。在功率路径禁能条件下采50%和至少一个不同CCR的CH2/CH2N原始波形，记录频率、高电平占比、幅度、边沿和互补关系。
2. **驱动与栅源层**：先确认驱动输入/输出及各源极参考点。高侧栅源测量按已确认的差分/隔离测量条件执行，不能把普通接地探头的地夹接到未知开关节点。分别记录两路Vgs、幅度、有效死区和可能重叠。
3. **采样相位**：用已确认的硬件触发/标记观测点，与PWM波形及ADC完成标记建立关系；记录标记从实际事件到GPIO的延迟。若没有可用观测点，只报告软件统计，采样相位保持缺测。
4. **CCR改变**：捕获请求前后连续周期，关联提交记录、后续UEV与实际新占空比；检查是否有不完整脉冲或超长周期。
5. **停止和故障**：用停止/故障标记触发，保留触发前后的CH2、CH2N及适用Vgs波形，测到最后有效驱动/栅源关断的时间。仅看到MCU低电平不能替代驱动截止证据。

每份波形保存原始导出、截图、通道映射、探头/参考点、耦合、带宽限制、采样率、存储深度、时基、触发配置、测量读数及固件哈希。截图和原始波形放 `evidence/runs/<run_id>/raw/`，复算与统计放 `derived/`，原始文件不覆盖。

|---|---|---|
| 上电/正常复位 | PWM引脚、驱动输出、继电器命令及适用触点状态 | 默认停机，无自动输出 |
| 正常STOP/重复STOP | 两路共同撤销、最后脉冲、驱动关断时限 | 停机；重复STOP不恢复 |
| 启动参数/时钟不符 | 拒绝启动，未出现输出脉冲 | 停机或锁存故障，原因可查 |
| ADC启动失败 | 清理前后MOE/通道/计数状态和实际引脚 | 禁能，无部分启动 |
| 软件故障注入 | 注入到MOE撤销、驱动/Vgs关断的时间 | 故障锁存 |
| ADC OVR/异常完成 | 原始错误、统计、输出撤销 | 故障锁存，错误不转为有效零 |
| 运行中复位/适用CPU fault | 复位前后引脚和驱动状态 | 不自动恢复输出 |
| 故障后再次START | 输出无恢复，记录拒绝原因 | 保持故障锁存 |
| 明确清故障后 | 清锁存本身不输出，重新检查启动条件 | 停机，须另行启动 |
| CCR更新与STOP相邻 | 停机后旧请求不得重新使能，保留边界波形 | 停机/故障锁存 |

## 7. 缺失输入与下一步

当前独立可做的是配置推导、软件实现、双target构建、故障注入与离线统计检查。它们支持对应的软件结论，不替代bench或release_boot证据，也不放行G03。

下一项可执行的实物工作是冻结G02无功率接线与测量条件：确认能量路径禁能方法、继电器/驱动有效电平、PA9/PF7可测点、探头参考方式和STOP操作；把确认事实写入profile。随后在具体烧录/测试授权下，新建run，先验证默认态和STOP，再进行50%逻辑PWM及内部ADC同步窗口。驱动/Vgs波形、有效死区、采样相位、输出关闭期限中任何缺测项均单独保留，不以寄存器值或断点代替。
